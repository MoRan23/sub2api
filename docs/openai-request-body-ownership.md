# OpenAI 请求正文的内存所有权

OpenAI 网关内部将接收到的 `[]byte` 视为只读数据。切片传参共享底层字节，不需要为每个串行处理步骤复制完整正文。

## 改写与重试

- 原始正文在整个请求期间保持不变，账号切换及重试从这个基线重新计算。
- 时区捕获、准备状态和账号目标投影共享只读正文，分别保存小型状态与补丁。
- 无补丁或补丁已经生效时返回原切片。修改字段时采用生成新正文的方式，不使用原地写入或 `sjson.ReplaceInPlace`。
- 返回内部共享切片的函数不能被当成可写缓冲区使用。需要可变存储的调用方必须显式复制。
- `PrepareOpenAIRequestTimezone`、`CloneRequestTimezoneState`、`PreparedBody` 等已有公开快照接口继续提供其约定的独立存储。

## 最终出站快照

最终化接口仍允许调用方持有并修改返回的正文，因此建立 HTTP 请求时保留一次独立复制。`Body`、`GetBody` 的各个 reader 共享这份私有快照，每个 reader 有独立的读取位置。

内部观测通过 `openAIUpstreamRequestBodySnapshot` 只读借用这份快照，不再使用 `io.ReadAll` 分配另一份完整正文。替换出站正文必须重新建立快照；不能把借用的字节用于原地改写。

## 身份字段与观测缓存

身份采集共用一次经过校验的顶层 JSON 只读视图。逻辑会话、线协议、请求回合、提示缓存键和安装标识从这份视图读取所需字段，`client_metadata` 只解码一次；不再分别解码或复制整段 `input` 历史。

字段优先级和无效元数据计数保持原有规则。安装标识原先允许读取尾随其他内容的第一个 JSON 对象，并替换无效 UTF-8 字节；这类异常输入仍走原有兼容解码，其他身份字段继续使用严格校验。最终保存的身份快照独立持有字符串和元数据，不能保留正文视图。

身份投影仅借用顶层 JSON 值，更新小型身份字段后一次写出最终正文。未修改的历史、密文、未知字段及大整数保留原始 JSON 值；重复顶层键保持标准 JSON 解码器的最后一项生效行为。

这些视图只在请求内部使用。放入观测环或分页快照的短字段必须拥有自己的字符串存储，避免短字段引用整份大正文。

## 验证

相关回归覆盖无修改时的分配量、改写后的账号隔离、公开快照的可变性、重放 reader 独立性以及观测字段脱离大型底层存储。可运行对应测试文件中的 benchmark 比较分配字节；这些测量只代表对应阶段，不等于整条网关链路的峰值内存。

身份采集的基准为 `BenchmarkOpenAIOAuthIdentityCaptureLargeHistory` 和 `BenchmarkOpenAIOAuthIdentityCaptureHTTPLargeHistory`。后者每轮创建新的 HTTP Responses 请求，包含 UA、流式标记及现有窗口识别流程，不复用已捕获身份。与 `f1c3e7268` 对比，Windows/amd64、Go 1.27.0、Ryzen 7 9700X 下各运行五轮的 HTTP 基准中位数为：

| 正文 | 优化前耗时 | 优化后耗时 | 优化前分配 | 优化后分配 |
| --- | --- | --- | --- | --- |
| 4 MiB | 33.77 ms | 11.55 ms | 54.00 MB | 8.45 MB |
| 64 MiB | 512.47 ms | 162.48 ms | 863.62 MB | 134.29 MB |

分配量是每次操作累计分配字节（MB 按十进制），不是驻留内存。HTTP 窗口识别等既有阶段仍有独立的解析与分配，本轮没有改写这些规则；上述数据也不代表线上 CPU 占用会按相同比例下降。

此次优化不更改入口正文大小限制、请求超时、账号调度或计费策略。
