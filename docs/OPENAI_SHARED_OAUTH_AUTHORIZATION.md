# OpenAI OAuth 共享授权与三系统身份

常规 OpenAI OAuth 凭据账号只保存一份 ChatGPT 授权。Windows、macOS、Linux
共用 access token、refresh token、授权状态及刷新过程；三套 UA、installation ID、
会话根和系统活动池继续独立。Spark 共用母账号授权，保留自己的业务账号归属。

官方 Codex 文档允许在本机登录后将 `auth.json` 复制到另一台机器使用，并未要求
为每个操作系统单独登录。这里的共享授权是本项目的存储和调度策略，不保证上游
授权永不过期。参考 [官方认证说明](https://learn.chatgpt.com/docs/auth?surface=cli#cli-fallback-authenticate-locally-and-copy-your-auth-cache)。

## 从三系统独立授权升级

升级前排空并停止所有旧服务进程，再执行迁移并启动新版本。不要混跑仍会独立刷新
系统授权槽的旧进程；新旧格式不能通过只回退应用二进制安全混用。

迁移 255 将授权收敛到账号级权威表 `account_openai_oauth_credentials`：优先选择
默认系统中状态为已授权且有可用凭据的完整授权；默认系统没有可用授权时，选择
其他现有已授权记录。已有 refresh token 的授权可尝试刷新；明确过期且没有 refresh
token 的 access token 不优先于其他可用授权。始终保留完整凭据快照，不拼接不同
授权的 token 字段，也不把已撤销或需要重新授权的记录恢复成已授权。

原系统授权表仅保留运行态版本与系统关联元数据，清空其中的凭据内容。迁移建立
新的共享授权代次，使旧授权的在途刷新、Cookie 和遥测任务不能写入新授权。
UA、安装 ID、默认系统和会话根不因授权合并重新生成。

## 请求与刷新

- 系统识别顺序仍为原始 UA、本轮可信独立环境上下文、账号默认系统。系统只决定
  出站身份，不再因该系统过去未授权而排除账号。
- 同一请求固定系统与授权代次。换账号后选择新账号的同系统身份；重新授权或撤销
  后，旧请求与长连接不能借用新授权继续发送。
- 刷新锁按凭据账号和共享授权代次隔离，三个系统竞争同一个刷新锁。token 缓存还
  保留版本隔离，防止拿到新 token 却用旧版本处理迟到错误。后台每账号刷新一次。
- 正常刷新保持授权代次和三系统身份。重新授权、撤销或不可恢复的认证失败影响
  共享授权；其他系统不能绕过失效状态。真实限流、账号并发与配额仍按原规则处理。
- 过期 access token 的 refresh token 无效时，前台立即用本次快照执行版本校验并
  标记需要重新授权。迟到失败不能覆盖已经刷新或重新绑定的新凭据。

## 管理操作

创建、重新授权、导入和撤销均作用于账号的一份共享授权。编辑页显示统一授权状态；
三个系统卡片只管理身份。切换默认系统不切换 token，也不要求再次授权。

手动连接测试仍可选择系统，含义是选择测试请求的 UA 和安装身份。次数查询、用量
刷新、自动重置和后台测试使用账号共享授权；没有指定身份时使用默认系统。用量卡片
可能先显示缓存，不一定发起上游查询。导出 `auth.json` 不再选择系统，导出只读、不
刷新、不访问上游。

新备份只导出共享凭据及默认系统配置，不生成三份授权。旧多系统备份兼容导入时
选择一份完整凭据，不合并 token 字段；私有授权代次、Cookie、池及根运行态均不复制。
普通账号编辑和后台旧快照仍不能覆盖受管凭据；OAuth/PAT/Agent Identity 模式变更
继续要求现有显式 `openai_auth_mode_change` 意图。

旧带 `os` 的授权接口保留兼容，参数不再选择独立授权；授权 state 仍绑定账号、
用途及共享授权代次并只能消费一次。账号主体与工作区校验不放宽。

## 系统池与适用范围

turn-state 的票据、需求和代理轮换仍按系统隔离。Cookie 按凭据账号、系统和共享
授权代次隔离，同系统跨模型和代理共享。遥测按系统及实际安装身份分池，使用该次
业务的身份和业务代理；发送前读取共享授权的最新凭据并校验授权代次。

API Key、PAT、Agent Identity、setup-token 和其他平台不受本次改动影响。凭据存储
沿用项目现有设施，不向普通账号摘要、日志或遥测公开 token 或私有授权代次。

验证记录见 [共享授权验证](testing/openai-shared-oauth-verification.md)。
