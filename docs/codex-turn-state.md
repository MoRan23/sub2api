# Codex turn-state 缓存与观测

账号创建或编辑页可开启 Codex turn-state 缓存，选择个人、Team / Business 或按已有套餐自动识别，并选择独立采集代理。默认关闭；仅支持常规 OpenAI OAuth。Spark 影子账号继承凭据母账号的设置和状态。未知套餐暂停缓存注入与采集，可手动选择分类。

全局生效模型名单默认是 `gpt-6-astra`、`gpt-5.6-sol`。`gpt-5.6-terra` 已移出默认名单，已保存的自定义名单不会被覆盖；管理员仍可手动加入其他模型。名单按最终上游模型 ID 精确匹配。

## 获取与续期

- 自然获取优先：成功交付的业务响应返回符合目标形态的状态后直接保存；满足采集或续期需求后取消同账号、模型的采集。
- 对应套餐的合法扩展形态触发采集：个人 312 字符 / 11 块，Team / Business 356 字符 / 13 块。没有状态、无效封装、套餐不匹配和未交付响应不建立新采集需求。
- 开启缓存时，最近 30 分钟内、当前凭据且成功交付的异常业务历史可触发采集。历史摘要不保存 token，正常历史不能变成可注入缓存。
- 本地有效期为签发后 60 分钟，到期前 5 分钟续采。重复收到同一状态不延寿；续期结果仍位于临期窗口时继续重试。采集未取得新目标时，仍有效的旧缓存继续使用。
- 普通失败或未取得目标状态后最早 30 秒重试。429 和账号冷却采用更长等待时间；401 / 403 暂停至凭据或配置变化。
- 仅维护最近 30 分钟有真实业务的模型，采集不延长这个窗口。空闲后结束需求；恢复使用先发正常业务请求。

采集与正常业务并行。已有异常需求或临期续期不等待业务请求结束，业务开始也不取消采集；业务返回同一临期 token 时继续续采。仍保留每凭据账号最多一个采集任务、限流退避和配置代次保护。并发结果按缓存内容与版本 CAS 校验，采集仅更新排队或退避状态不会使业务缓存快照失效；重复异常业务不会挤掉较新的合格采集结果，迟到异常和采集结果不能覆盖业务新取得的目标状态。

每次采集使用当前 OAuth 凭据、最终模型和指定采集代理，向 Responses 接口发送一条独立短请求，超时 20 秒。采集不使用业务正文、原 turn-state 或 continuation，不进入插件转发、模拟遥测、每日会话根或下游计费。采集是上游模型请求，可能消耗账号额度。

采集 JSON 正文对齐 `ccodex-sleep-state@b18fabf9`：instructions 和用户消息均为 `Reply with OK.`，消息明确标记 `type: message`，设置 `stream: true`、`store: false`、`parallel_tool_calls: true` 及 `include: ["reasoning.encrypted_content"]`。不指定 reasoning effort，使用上游默认值；账号身份头和独立采集请求 ID 仍由本项目生成。

HTTP 429 和 SSE 失败事件中的结构化错误码 `rate_limit_exceeded` / `insufficient_quota` 均记为采集限流，沿用账号级退避。SSE 限流保留真实 HTTP 状态，不从错误文本猜测；重试时间取 30 秒、响应头 Retry-After 及账号已有冷却中的最晚值。失败响应中的 token 不发布为缓存，已有有效缓存和脱敏观测按原规则保留。

未配置采集代理时仅从业务响应学习；代理不可用时显示失败原因，不切换到业务出口。没有可用缓存时照常转发业务，不等待采集、不阻断、不重放。

## 观测与页面

轻量观测独立于缓存开关和指纹观测开关，每模型保留本实例最新实际返回的状态摘要。业务与独立采集均可更新摘要，详情标明请求来源及响应头 / metadata 载体。没有返回状态的请求保留原摘要和原时间。重启会清空这些本实例摘要；已加密保存的缓存和采集需求仍在数据库中。

账号列表优先按生效名单显示“状态点 + 模型名”，最多 5 行；不足 5 行时，其他模型产生实际观测后动态补入，不留占位行。超过上限的模型在详情查看。颜色依据最新观测；没有观测时参考当前有效缓存：

- 绿：符合对应套餐的目标形态。
- 红：已观测到对应套餐的有效扩展形态。
- 灰：没有状态、无法分类或无法可靠判断。

缺缓存不会自动显示红色；已知异常正在重试时仍为红色。刷新期间保留内容和颜色，收到新结果后更新。弹窗桌面端左列缓存、右列最近观测，小屏上下排列；打开时每 5 秒刷新。“最早可重试时间”不是保证发送时间，仍受采集单飞、队列和账号状态约束。业务在途不再显示“等待业务请求完成”。采集暂停不代表仍有效的缓存不能使用。

## 存储与升级

迁移 `245_openai_codex_state_credential_epoch.sql` 初始化私有凭据代次；`246_openai_codex_state_demand.sql` 增加持久化需求、采集阶段和历史消费水位。沿用现有迁移机制应用。普通用量更新不会使缓存失效；凭据或缓存配置变化受行锁和版本保护。私有代次、运行态和 token 不参与账号导入导出。

PostgreSQL 是缓存权威来源，Redis 用于跨实例互斥、取消和配置激活通知。每实例最多 4 个采集 worker，每个凭据账号跨实例最多一个采集任务。存储不可用时恢复原业务行为，不依赖旧本地缓存继续注入。

状态接口 `GET /admin/accounts/:id/codex-turn-state` 及批量接口仅返回脱敏摘要。模型状态增加 `cache_available`、`collection_status`、`collection_reason`；观测增加 `request_source`（`business` / `collector`），与 `response_source`（响应载体）分开。页面读取不会触发采集。

长度和块数是加密封装的可观察形态，不是 HTTP 状态码，也不证明模型质量。系统检查 Base64url、Fernet 封装及签发时间，不解密或验证未知密钥的签名；60 分钟是本地维护策略。
