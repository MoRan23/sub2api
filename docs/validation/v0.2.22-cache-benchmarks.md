# v0.2.22 cache benchmarks / 缓存基准

Baseline `08a02ad7f` and the merged worktree were compiled with Windows Go 1.27.4, `GOEXPERIMENT=greenteagc,jsonv2`. Runs used `GOMAXPROCS=4`, the same synthetic data, `-test.benchmem -test.benchtime=1s -test.count=1`, three alternating baseline/merged rounds. No production services were used.

## Shared scheduler candidates / 共享候选快照

Fixture: 2,000 accounts, 100 groups, shared accounts; `BenchmarkSchedulerCacheReadSharing/accounts_2000_groups_100`.

| Round | Baseline ns/op | Merged ns/op | Baseline B/op | Merged B/op | Baseline allocs/op | Merged allocs/op |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1,138,975 | 148,662 | 421,777 | 50,745 | 10,338 | 61 |
| 2 | 1,245,274 | 146,839 | 421,775 | 50,745 | 10,338 | 61 |
| 3 | 1,071,524 | 153,865 | 421,775 | 50,745 | 10,338 | 61 |

Median read time decreased **87.0%**, allocation bytes **88.0%**, and allocation count **99.4%**. The fixture's p95 read latency changed from 2.034 ms to 1.002 ms (−50.8%). Its decoded-retained measurement changed from 46,251,416 to 47,907,208 bytes (+3.6%); it includes fixture/runtime retention and is not process peak RSS.

本次数据反映缓存热读及 LastUsed 短缓存的变化。常驻增量主要来自 100 个分组各自缓存的 2,000 项 LastUsed 指针数组：按 Go 分配档位约 1.64 MB，与实测增量吻合。完整账号仍按唯一内容共享；侧缓存纳入软预算，替换或分组淘汰后释放。该夹具没有实际 LastUsed 值，不分配时间对象数组，并使用固定时钟测量缓存命中路径。保留堆与逐次分配分别报告。

## Catalog projection / 目录投影

Fixture: `BenchmarkGroupCatalogRepresentationComparison/{baseline_rebuild,cached_304}`. The `baseline_rebuild` name identifies the uncached fixture variant, independently of the tested Git revision.

| Round | Baseline rebuild ns/op | Merged rebuild ns/op | Baseline cached 304 ns/op | Merged cached 304 ns/op |
| --- | ---: | ---: | ---: | ---: |
| 1 | 4,068,378 | 3,873,300 | 46,137 | 43,646 |
| 2 | 3,858,746 | 4,125,903 | 40,054 | 41,279 |
| 3 | 3,741,102 | 3,742,944 | 44,580 | 44,882 |

Median rebuild time changed +0.4%, cached 304 −2.1%. Rebuild allocations remained approximately 1.46 MB / 84 allocations; cached 304 approximately 27.3 KB / 39 allocations. These small timing differences lie within the observed run variation.

## Reproduction and raw records / 复现与原始记录

Compile the repository and service test binaries at each revision with the same benchmark fixtures, then run:

```sh
export GOMAXPROCS=4 GOEXPERIMENT=greenteagc,jsonv2
./repository.test.exe -test.run '^$' \
  -test.bench '^BenchmarkSchedulerCacheReadSharing$/^accounts_2000_groups_100$' \
  -test.benchmem -test.benchtime=1s -test.count=1
./service.test.exe -test.run '^$' \
  -test.bench '^BenchmarkGroupCatalogRepresentationComparison$/^(baseline_rebuild|cached_304)$' \
  -test.benchmem -test.benchtime=1s -test.count=1
```

Repeat three times per revision, alternating baseline and merged binaries. Raw records are under [v0.2.22/raw](v0.2.22/raw/), named `scheduler-final-{baseline,merged}-r{1,2,3}.log` and `catalog-final-{baseline,merged}-r{1,2,3}.log`.
