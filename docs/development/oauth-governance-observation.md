# OAuth 配置保护、连接隔离与完整性观察

## 配置写入约定

- installation UUID 由创建、修复 CAS 和专用再生接口维护；普通保存不能写回旧 UUID。再生操作在数据库行锁内重新检查账号类型、影子关系与 pin 状态。
- pin、环境 UA、TLS 开关和模板的未提交字段，使用事务内读取的数据库最新值。后台凭据持久化、CRS 同步和旧账号快照不具有修改这些配置的权限。
- 修改 UA 使用现有 `openai_environment_fingerprint` 专用字段。直接回写 `credentials.user_agent` 的脚本需要改用该字段；OAuth token 条件更新规则保持不变。
- TLS 关闭必须明确提交 `extra.enable_tls_fingerprint: false`；清除模板选择必须提交 `extra.tls_fingerprint_profile_id: null`。省略字段或 `extra: {}` 不再隐式关闭 TLS。
- 旧客户端明确提交的 pin／TLS 值继续视为主动编辑。pin 仍由单账号编辑入口修改，批量和独立 Extra 更新入口原有的 pin 限制不变。
- 编辑弹窗只提交相对打开时初值真正改变的保护字段；这不提供整账号版本冲突检查，也不扩大到配额、代理或并发字段。

## 连接与限流

TLS 模板仍来自内置参数或管理员保存的模板，没有增加或验证新的 Codex 模板。HTTP 模板传输保存深复制快照，按账号、代理摘要、模板完整内容（包括数组顺序）及现有 upstream profile 隔离。修改模板或代理后，新请求不复用旧传输；在途请求沿用旧传输直到结束。

WebSocket 客户端缓存和物理连接匹配增加账号、目标、代理及实际标准 TLS 传输标识。没有启用新的 WS uTLS 握手，也没有替换原有读循环、线程作用域、队列和重连机制。代理日志不输出 userinfo。

普通限流写入原子地只延长冷却；管理员清除和带观测版本的替换仍是独立操作。普通 429 优先使用有效平台 reset，其次使用 `Retry-After`，最后使用默认冷却。关闭默认冷却不会忽略上游明确的等待时间。

## 完整性观察

`openai_request_integrity_observe_enabled` 默认开启。迁移仅补充缺失设置，不覆盖已有显式值。开关按请求或已接受的 WS turn 冻结，与固定根、指纹采集及遥测开关独立；仅支持观察或关闭。

原生 Responses 保存账号适配前的基线。Messages／Chat 保存首次转换成 Responses 后、Codex 适配前的基线，页面明确标记“转换后基线”，不声称验证了协议转换器本身。物理重试和换账号仍比较同一基线；每个新 WS turn 建立新基线和尝试计数。

每次实际 HTTP body 或 WS frame 发送前进行只读比较。结果分为无差异、符合已知转换规则、发现差异、未完成检查。有限的模型映射、已冻结时区补丁、工具形状与别名、固定兼容说明等使用明确规则；未知变化仍报告差异。删除加密 reasoning、历史重放等恢复可以继续执行，但不会因此宣称内容未改变。

检查只覆盖 OpenAI OAuth 普通推理；API Key、Agent Identity、图片与内部辅助请求不在范围内。检查器不修改正文、不拒绝请求、不控制重试或换号。每份正文最多 8 MiB、深度 128、节点 16,384，最多记录 32 个差异位置；解析失败、缺基线或超限显示未完成检查。

页面复用现有指纹条目中的可选 `request_integrity` 摘要。关闭指纹采集时不会创建条目，差异／跳过日志仍有效；正常结果不逐请求刷日志，同账号同原因限频并汇总抑制数。摘要和日志不保留正文、字段值、凭据或正文哈希。

## 验证边界

新增测试使用本地 HTTP/TLS/代理/WS 或内存发送器，不依赖真实上游。包括配置保护、token CAS 回归、Retry-After、模板快照、连接隔离、固定根开关、兼容入口、WS 多轮、HTTP bridge、物理重试、换账号和观察关闭时的发送内容不变。

当前 Windows 环境无 Docker：数据库集成测试只做编译检查，未执行数据库断言；测试入口检测 Docker 后跳过的退出码 0 不代表数据库验证通过。
