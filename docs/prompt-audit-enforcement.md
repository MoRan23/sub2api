# 提示词审计：关键词分类、违规计数与自动封禁

本文说明关键词分类和组合规则的处罚行为，以及升级、回退要求。配置仍使用管理员提示词审计页面和现有 `GET/PUT /api/v1/admin/prompt-audit/config` 接口。

## 配置与默认值

| 字段 | 默认值 | 含义／范围 |
| --- | --- | --- |
| `jailbreak_keywords` | 旧 `blocked_keywords` 的全部词条 | 破甲关键词；每行一条，支持字面词和 `regex:` |
| `other_keywords` | `[]` | 其他关键词；只拦截和记录审核事件 |
| `warning_email_enabled` | `true` | 为新的破甲／组合命中创建警告邮件任务 |
| `warning_email_window_minutes` | `5` | 邮件固定合并窗口，1–60 分钟 |
| `auto_ban_enabled` | `true` | 新命中达到阈值时自动停用普通用户 |
| `violation_window_hours` | `24` | 滚动统计窗口，1–720 小时 |
| `ban_threshold` | `10` | 达到此次数即触发自动封禁，1–10,000 |

两类关键词规范化后合计最多 10,000 条。字面词每条最多 200 个 Unicode 字符；每条正则规则（含 `regex:` 前缀）最多 2,000 个 Unicode 字符，继续使用 Go/RE2 校验。关键词总开关 `keyword_blocking_enabled` 控制两类词表，组合规则仍由 `combination_policies` 中各规则组的 `enabled` 控制。现有风控总开关、关键词分组范围和精确到“用户＋API Key”的白名单继续生效。

这些新字段在更新请求中省略时保留当前设置。显式传 `jailbreak_keywords: []` 或 `other_keywords: []` 清空对应列表；清空两类列表时也须关闭关键词总开关。旧客户端的 `blocked_keywords` 仍作为破甲列表的兼容写入入口；同时提供新旧字段时，以 `jailbreak_keywords` 为准。旧列表不会被自动按内容分类。已配置的组合规则迁移规则仍可移除两类列表中明确指定的精确词条。

升级后，原来已启用的旧关键词规则会以破甲类别生效，并使用默认处罚设置。上线前应检查分类；需要保留普通关键词行为的词条应移动到“其他关键词”。

## 匹配、响应与计数

本地检测顺序为：**破甲关键词 → 主题与意图组合规则 → 其他关键词**，之后才进入原有审核流程。按此优先级选择一次实际拦截，同一请求命中多个词或多个类别只产生一次处罚计数。

- **破甲关键词**：返回 403，错误码 `prompt_keyword_blocked`。提示禁止破甲、停止使用破甲词，并显示已提交的窗口内记录次数；不返回命中词、内容片段或正则。
- **组合规则**：返回 403，错误码 `prompt_combination_blocked`。仅展示规则组名称、停止违规请求的提示及记录次数，不返回主题／意图片段和规则内容。
- **其他关键词**：保留原有 403 和实际命中内容提示，不泄漏完整正则；只写审核事件，不累计本功能的处罚次数、不自动封号，也不发送本功能的警告邮件。
- 外部 Guard 的事件仍走原有处理，不参与本功能的处罚。外部响应不能伪造本地关键词类别及保留证据字段。

计数按用户汇总，跨该用户的 Key 和命中类别合并。HTTP 请求和实际 WS 回合使用服务端生成的唯一标识；数据库以“用户＋请求标识”去重。重试、重复完成和多实例重复提交不会增加同一请求的次数，客户端提供的请求 ID 不能控制去重。重复返回使用该次已提交的计数快照。

默认在当前计数周期的最近 24 小时内达到 10 次时停用用户。保存设置本身不会追溯执行封禁；下一次有效新命中才检查当前阈值。管理员角色仍会被拦截、记录和计数，但不由此功能自动封禁。已经被其他原因停用的用户不会被本功能接管。

事件、命中账本、用户状态及邮件任务在一个事务中提交。事务失败时请求仍被拦截，响应显示“记录次数暂不可用”，不会虚报记录成功或自动封禁。请求开始时间也由服务端冻结；解封前开始、解封后才完成的迟到拦截只保存真实事件，不进入新周期。

## 开关和历史

| 操作 | 后续行为 |
| --- | --- |
| 关闭关键词总开关 | 停止两类词表检测；仍启用的组合规则照常工作 |
| 关闭某个组合规则组 | 停止该组的新检测；其他规则照常工作 |
| 关闭 `warning_email_enabled` | 新命中继续拦截、计数和按设置封禁，但不创建新邮件任务；已提交邮件任务继续处理 |
| 关闭 `auto_ban_enabled` | 新命中继续拦截、计数，并按邮件设置通知；不新增自动封禁 |
| 删除审核事件 | 删除对应审核详情，不重置处罚计数 |

上述开关及时间窗口自然流逝都不会自动恢复已经停用的用户。命中账本独立于审核详情保留：至少覆盖最长可配置窗口及一天重叠时间（31 天），有关联审核事件的记录继续保留。旧历史没有新增分类或处罚快照时显示“未分类／未记录”，不推算旧规则、不追溯计数或封禁。

事件响应新增可选 `keyword_kind`（`jailbreak`／`other`）及 `enforcement`。其中 `violation_count`、`window_hours`、`ban_threshold`、`auto_banned`、`epoch` 记录当次事实；`user_status` 和 `can_unban` 按当前用户状态及封禁归属读取。邮件状态为 `not_requested`、`queued`、`sending`、`sent`、`retry`、`failed` 或 `cancelled`。

## 快捷解封与管理员状态操作

管理员页面根据当前 `can_unban` 展示快捷解封；接口为：

```text
POST /api/v1/admin/prompt-audit/users/:user_id/unban
```

解封检查的是**用户当前的提示词审计封禁归属及版本**，不要求当前封禁属于页面正在查看的历史事件周期。成功时恢复 `active`、开启新的计数周期、清除自动封禁归属并取消旧周期未发送的邮件；历史事件和命中账本保留。已经启用的用户返回 `already_active`，重复解封不会再次重置周期。若当前停用不属于提示词审计，接口返回 409 `prompt_audit_unban_ownership`，应到用户管理处理。

在用户管理中显式写入用户状态，包括重复提交 `disabled`，都会撤销提示词审计的自动解封归属。显式写入 `active` 还会开启新周期并取消旧周期待发邮件。未明确修改状态的普通资料更新保留现有归属。自动封禁沿用停用用户时撤销管理 MCP 授权的规则；重新启用不会恢复已经撤销的授权。成功提交状态变化后刷新用户鉴权缓存。

## 邮件合并与投递

同一用户、同一周期的未发送警告从首个命中起固定等待默认 5 分钟；后续命中合并，不把截止时间不断后推。窗口内达到封禁阈值时，未发摘要升级为可立即领取的封禁通知。邮件只包含类别、可选规则组名、次数、窗口、阈值和账号状态，不包含原始提示词、关键词、正则或命中片段。

邮件采用数据库持久化任务、两分钟领取租约及版本检查；SMTP 在事务外执行，单次投递调用受 45 秒超时约束。每个待投递版本最多进行 **5 次投递尝试（包含首次）**，失败后有界退避，最终显示 `failed`。发送期间的新命中单独保留，完成确认只消费已领取的部分。服务重启后可继续领取未完成任务。SMTP 已接收、但数据库确认未成功时可能重新投递，这是投递确认边界，不影响命中次数或封禁事务。

解封／显式启用后，尚未开始的旧周期邮件会失效；已经交给 SMTP 的邮件无法撤回。关闭邮件开关只影响新入队，需结合邮件状态判断已有任务。

## 升级与回退

1. 备份数据库、提示词审计配置及当前应用版本；在测试环境核对旧词迁移后的分类和默认处罚开关。
2. 排空旧进程，统一切换应用版本。避免新旧版本同时写入关键词配置、用户状态和处罚状态。
3. 启动时执行向前迁移 `281_prompt_audit_enforcement.sql`。该迁移只新增处罚状态、命中账本、邮件任务三张表及索引，不修改历史事件或自动启用用户。
4. 检查管理员配置、规则分类、普通关键词行为、解封入口及邮件任务状态。用模拟请求／测试用户和测试邮件通道验证，再启用实际策略。

回退时停用新版进程，恢复相匹配的旧应用和配置备份。旧版本只识别 `blocked_keywords`，不理解双分类和新处罚行为；保存好新版配置备份，回切新版时使用。新增表可保留供后续升级，旧程序不会继续本功能的计数、封禁及邮件处理。数据库中的既有 `disabled` 用户不会因回退自动恢复，应由管理员按当前状态逐个处理。需要恢复整个数据库时，使用与应用匹配的一致备份，并评估备份之后业务数据的恢复安排。

本文是本地实现的操作说明；实际部署和真实 SMTP 投递需在对应环境验收。
