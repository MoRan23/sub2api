# 降智检测

管理员在侧边栏「降智检测」配置 ModelTrace 服务地址、探针模型及高低级白名单。
迁移 `263_model_attribution.sql` 初始关闭自动检测，默认探针模型为 `gpt-6-astra`。
服务地址及两份非空白名单配置完成后才能开启。模型选择器支持手动输入具体模型 ID。
「测试连接并获取候选模型」只查询指纹库；实际归因探针会消耗上游账户额度。

## 检测和分组

- 每个符合条件的 OpenAI OAuth 实体账户每 10 分钟开始一轮检测；扫描间隔 30 秒，不同账户同时执行。
- OpenAI API Key 账户支持单账户及批量手动归因检测，包括通用、透传及 Codex-Engine 接入模式；不参与十分钟周期检测或新账号自动首测。账户列标注「仅手动」。手动检测只需配置 ModelTrace 地址，不要求开启自动检测；不受停用、关闭调度、过期、透传、影子账号或本地限流标记限制。仍需账户存在、授权有效，且仅支持 OpenAI OAuth / API Key 账户。
- 手动弹窗支持从 ModelTrace 候选列表选择模型，也可输入具体模型 ID；默认跟随各账号的分组 / 全局模型。所选模型同时作为本轮期望模型，保存到任务快照，不修改自动检测配置。继续沿用同账号活动任务去重、授权变更保护及十分钟执行期限；再次点击返回已有任务，不覆盖它的模型。
- 全局配置提供「分组优先级」排序列表（`group_priority`），越靠前越优先。多个分组的账户先选定优先级最高的所属分组，再取配置：启用独立配置时采用其高级、低级白名单及探针模型；继承全局或未设置独立配置时采用全局配置，不再跳到后面的分组。未列出的分组按 `account_groups.priority` 升序、分组 ID 排在后面，也参与选择。记录中保留选中的分组 ID；无所属分组时使用全局默认，分组 ID 为零。
- 探针模型也是期望模型。三条独立探针依次使用所选账户的 OAuth 或 API Key 授权及账户代理执行；OAuth 使用默认授权环境。绕过业务白名单与模型映射，不提供工具、不修改健康状态、不产生下游用户扣费。
- 归因和鹈鹕共享有限重试：临时上游连接失败、响应超时、流中断、HTTP 408/500/502/503/504 等最多额外重试 2 次，分别等待 1、2 秒。成功的探针不重复，整轮仍受原 10 分钟（鹈鹕 30 分钟）期限限制。授权变化、主动取消、请求参数错误、输出超限或 HTML 异常不重试；每次重试保留初始授权保护，并检查归因配置是否仍有效。详情记录重试次数和全部已报告用量，重试会消耗上游额度。
- 当前账号或直接请求的探针模型被本地标记限流时，自动归因及鹈鹕测试跳过；手动归因忽略本地标记。实际 HTTP 429 或流内明确的限流错误仍立即停止，不重试、不继续后续探针，也不修改模型名单。过期限流标记不阻止检测；周期检测在限流解除后恢复，新账号首测跳过后不补发。诊断请求仍不改写账号健康状态。
- 停用、关闭调度、过期、删除、自动透传的 OAuth 账户和共享凭据的影子账户仍跳过自动检测。
- ModelTrace 通过 `GET /api/banks`、`GET /api/challenges`、`POST /api/analyze` 提供模型库、题目和概率。仅发送题目回答和期望数量，绝不发送账户令牌。
- ModelTrace 未收录期望模型时，不发送模型探针。服务不可用、回答未全部有效、概率无效或最高概率并列都记为异常。

账户列表「归因测试」列分别显示活动任务与最近结束的结果，支持单账户和批量立即测试。手动测试与自动测试共用去重与名单切换规则。关闭归因弹窗不触发账户列表刷新。

## 新 OAuth 账号首测

「降智检测 → 新 OAuth 账号首测」提供归因、鹈鹕两个独立开关（默认开启）及独立模型：`attribution_model` 默认 `gpt-6-astra`，`pelican_model` 默认 `gpt-6.1-sol`。归因首测还要求全局检测已经配置并启用；鹈鹕首测独立于全局检测开关。模型级限流分别检查各自模型，不阻止另一种未限流的首测；账号整体限流仍跳过两种测试。

设置仅影响保存后新建或导入的 OpenAI OAuth 实体账号，不补测旧账号。创建时保存首测选择，每 3 秒检查并启动；停用、关闭调度、过期、删除、自动透传及影子账号跳过。启动前再次检查当前开关，已手动测试的账号不额外重复首测。两种测试消耗上游额度，采用上述临时错误重试规则。

归因首测使用首测模型作为期望模型，名单仍按分组规则选择；后续十分钟周期使用原全局 / 分组探针。关闭归因首测只取消这一次即时测试，不关闭周期检测。首测和周期模型不同会分别建立有效判定基线。

迁移 `264_new_account_tests.sql` 新建创建事件表。账号、首测事件同事务保存；两种测试的入队与事件消费也同事务提交，多实例、重启及历史清理都不重复触发。每个账号仅一条事件，不保存令牌或回复，物理删除账号后级联清理。

迁移 `265_split_initial_test_models.sql` 拆分模型配置并递增配置版本。旧共用模型保留为归因首测模型；鹈鹕的旧默认 `gpt-6-astra` 更新为 `gpt-6.1-sol`，其他自定义共用模型保留。已创建事件保留原有模型，保存新配置不会改写待启动任务的模型，也不重放已完成任务。

## 白名单规则

最高概率模型 ID 必须与探针模型 ID 完全一致才算通过，不另加概率阈值。

| 当前结果 | 连续通过次数 | 行为 |
| --- | --- | --- |
| 通过 | 第一次 | 保持当前白名单，等待再次通过 |
| 通过 | 连续第二次 | 应用高级白名单，内容相同不重复写入 |
| 通过 | 已确认连续两次 | 不修改 |
| 不通过 | 任意 | 应用低级白名单，内容相同不重复写入 |
| 失败 / 异常 / 跳过 | 任意 | 不修改，不覆盖有效判定，打断连续通过 |

每轮包含三条探针，连续两次指两轮完整检测均通过。首次检测及降级后恢复均需连续通过两次；不通过、执行失败、异常、已跳过、超时、中断或过期结果会将连续次数清零，未启动的周期扫描不计作一轮。详情显示「已通过 1 次，等待再次通过」及连续次数（最多显示 2）。
配置版本或有效分组策略变化后重新累计：不通过立即同步低级名单，通过需连续两次才同步高级名单。OAuth 普通刷新保留基线，重新授权或更换探针模型后重新建立基线。
手动测试也使用已配置的高低级名单；未配置完整两份名单时只保存结果，不清空模型映射、不标记名单已同步。手动选择不同模型的判定不会被当成自动模型的已同步基线。
API Key、上游地址或 Codex-Engine 接入模式变化同样重建基线，并阻止旧任务回写名单；仅保存授权摘要，不持久化密钥到检测记录。

更新只替换 `credentials.model_mapping` 中 `key == value` 的白名单条目；别名、通配符及冲突键的原映射保留。这些映射继续按现有业务路由规则提供访问。

结果应用、JSONB 字段更新、有效判定、连续次数和调度缓存 outbox 事件处于同一事务，不覆盖其他凭据字段。回写前重新核对配置、授权代次、分组及模型映射；检测期间的配置或人工修改使结果过期，仅保留记录。未提交的名单变更不记为同步成功。

迁移 `266_attribution_consecutive_passes.sql` 为有效判定表增加连续次数。升级时从零开始累计，不推算历史记录、不立即修改已有白名单。

## 执行和存储

- PostgreSQL 唯一活动任务索引与事务锁保证同一账户的同类测试不重叠，支持多实例。取消全局三账户容量限制，领取后立即并行执行，不等待其他账户结束。保留数据库 `queued` 状态作为创建到领取的短暂启动阶段，界面显示「启动中」；不用于限流排队。鹈鹕重复触发标为已跳过，旧版尚未开始的重复任务也会跳过，不追加到后续执行。
- 运行租约 45 秒，每 10 秒续期；续期/校验有 5 秒上限，整轮最长 10 分钟。
- 过期任务终止并记录中断/超时，不重新发送已运行请求；停机期间的周期不补发。
- 每账户只保留最近 100 条已结束任务。有效判定和连续次数独立存储，重启与历史清理不影响恢复。
- 不持久化原始回答或 OAuth 令牌。详情包含配置快照、概率、有效性诊断、用量和名单变更。
- 配置保存使用版本校验，冲突返回 HTTP 409。

管理员 API 前缀为 `/api/v1/admin/model-attribution`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / PUT | `/config` | 读取 / 按版本保存配置 |
| POST | `/models` | 检查连接及查询候选模型 |
| POST | `/jobs` | 为 `account_ids` 创建手动去重任务；可选 `model` 只覆盖本轮探针 / 期望模型 |
| GET | `/jobs` | 分页查询，可传 `account_id` |
| GET | `/jobs/:id` | 结果详情 |

## 本地验证

使用模拟 ModelTrace、模拟上游及独立 PostgreSQL/Redis 容器，没有真实模型或支付请求。

- Go：配置选择、跳过条件、三探针链路、数值验证、上游失败、取消/超时、绕过名单、既有鹈鹕传输/OAuth 刷新回归。
- PostgreSQL/Redis：连续两次通过、首次通过保持名单、失败/异常/跳过打断、降级恢复、配置更新、全局分组优先级、令牌刷新、授权/人工变更防护、事务回滚、缓存 outbox 生效、并发去重、超过三个账户并行领取、租约过期、不重放、100 条保留、重复迁移。
- 前端：相关 Vitest、类型检查、i18n 完整性、生产构建、改动文件 ESLint；实际 Chrome 模拟接口检查配置页、侧边栏、账户列、详情、任务创建和鹈鹕 iframe。
- Go vet 和 Windows/Linux 服务端构建通过。

部署后由管理员配置并启用；本次开发交付不执行部署。
