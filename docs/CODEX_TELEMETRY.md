# Codex 三系统遥测与真实观测

后台「系统设置 → 网关服务」提供遥测总开关，以及「模拟客户端行为」和
「真实请求观测」两个子开关，三个开关默认开启。适用于常规 OpenAI OAuth
账号，Spark 使用母账号身份池并保留实际业务账号归属。API Key、PAT、Agent
Identity、账号测试、独立 turn-state 采集、预热及内部维护请求不驱动这些池。

事件、OS 标签、计时和指标语义依据本地 Codex 0.155.1 源码快照核对。
这不是完整 Codex 客户端：模拟的工具、命令、文件修改、hook、Guardian、
标题和启动事件不表示网关或用户机器实际发生过这些行为。

## 模式与来源

| 模拟 | 真实观测 | 行为 |
| --- | --- | --- |
| 开 | 开 | 真实字段优先，模拟补缺；同一事实不重复计数 |
| 开 | 关 | 使用系统池模拟活动，不将模拟值标成实测 |
| 关 | 开 | 只记录有证据的请求事实；必填客户端证据不足时跳过事件 |
| 关 | 关 | 不采集或发送遥测 |

设置字段为 `codex_telemetry_enabled`、`codex_telemetry_simulation_enabled`、
`codex_telemetry_observation_enabled`，总开关控制两个子开关。来源
`observed`、`simulated`、`mixed`、字段来源和推定原因仅用于本地诊断，
不新增到官方遥测报文。

**发送成功只表示遥测端点接收成功，不表示模型路由、账号质量或账号状态改变。**
目前没有证据证明模拟遥测可以改变模型路由。

## 三系统身份和活动

池按凭据账号、系统和**实际出站 installation ID** 分区，使用业务请求冻结的
身份计划和最终请求头核对。没有携带 installation ID 时使用缺失分区，不把
受管 ID 描述成已发送；系统不能可靠识别时跳过依赖系统的模拟。Windows 请求
只驱动 Windows 池，没有业务的系统不会因定时任务制造活动。

| 系统 | 缺省模拟 shell | 平台行为 |
| --- | --- | --- |
| Windows | PowerShell | 不模拟 shell snapshot 成功；未知 MXC 能力不冒充可用 |
| macOS | zsh | Apple Silicon 规范化为 `aarch64`，OTLP OS 标签使用 `Mac_OS` |
| Linux | bash | 保留可识别的发行版，不产生 Windows 专属指标 |

可信请求信息优先于模拟缺省。未知权限采用模拟的 `read_only`、受限网络和
`on-request`；sandbox 权限策略与 `seatbelt`、`seccomp` 等实现标签分开。
只读场景不模拟成功文件写入。每池持久化场景种子及模板版本，每回合的工具、
命令和文件抽样只执行一次，重试不重新抽样。hook、Guardian、标题和相关指标
共用活动事实，保持开关、次数、结果、关联 ID 和时间一致。

池及启动、线程初始化去重标记持久化到 PostgreSQL。进程重启、代理切换、
账号改名、OAuth 正常刷新、每日根切换不重建池。安装身份变化启用对应新池，
旧池数据不迁入新池。池和私有运行态不参与账号导入导出。

短期 turn、attempt、sampling 活动在完成或被标记未完成后保留七天，各池的
短期活动同时受 4096 条状态上限保护，容量紧张时优先清理最旧的已完成记录。
仍有业务在途的状态不会为腾出容量而伪造完成；无法容纳时跳过新增遥测。
稳定的池种子、进程启动和线程初始化标记不参加短期清理，静默后不会重新
制造启动事件。

运行系统、客户端家族、指标生产进程和执行 sandbox 分别建模。例如 app-server
可以使用另一系统上的执行服务，不能只凭 UA 推断执行权限。业务代理、UA 和
版本按批次冻结，不额外向 OTLP 发送 installation ID 等私有标识。

## 回合和指标语义

HTTP、Responses 透传、Chat/Messages 转 Responses、HTTP/WS bridge 和原生 WS
使用相同归组规则，区分用户回合、sampling 和物理尝试。一次
`response.completed` 只证明一次 sampling 结束，不证明客户端回合结束。

同线程出现新的明确 `turn_id`，且旧回合没有在途请求、待回传工具或明确继续
要求时，才封存旧回合的模拟摘要。`end_turn:false` 和待回传工具保持回合开放；
`end_turn:true`、`final_answer` 不覆盖这些条件，也不是实测客户端完成证明。
缺少 turn ID 时使用请求级关联键，不把整个根会话合并成一回合。无在途请求且
静默 30 分钟的未封存回合标记未完成，不推定成功。迟到结果不重发已封存摘要。

业务在途记录使用 90 秒租约，由所属实例每 30 秒续一次心跳，心跳不延长真实
业务活跃时间。活着的长请求不会因持续时间超过 30 分钟而被误判为静默；实例
退出或请求上下文取消后停止续租，租约到期后再按静默规则处理，不制造成功或
主动中断事件。取消后的适配器有一个租约周期用于记录最后响应。

首帧、首个有效模型输出、首条 AgentMessage、发送耗时和逐事件等待分别记录。
`response.created` 不是 TTFT，推理和工具参数不代替首次 AgentMessage。WS 按
实际事件计数并排除 Ping/Pong。上游终态与网关交付、重试决策分开；断连不
冒充用户主动中断，失败不被迟到完成事件改成成功。

客户端重试不能用“请求次数减一”推算，后续工具 sampling 不等于传输重试。
工具输出只证明网关看到了相关输入，不能证明真实执行耗时、hook 或审批结果。
完整客户端耗时和无法观测的本地行为不能标为请求实测。

指标使用共享的 60 秒 Delta 周期，时间范围是初始化或上次采集至本次采集。
已封口批次不再修改。持续时间和普通数值使用不同直方图桶。Statsig 输出遵守
官方排除名单；服务端内部 timing 仅记录实际返回且有效的允许字段。HTTP 请求
不制造 WS 成功指标。

当前指标目录包含 70 种定义，按场景、平台、模式及官方 Statsig 排除名单选取；
这不意味着每个账号、每个平台或每个批次都会发送全部定义。

自动审核、审核者和 Guardian V2 分别处理，不用自动审核推断 Guardian 开关。
真实 Guardian 请求保留其身份、响应与用量，不套用普通用户的模拟活动。
来源线程不明确时省略来源关联，不用每日根替代未知来源子线程。

## 持久化与故障处理

PostgreSQL 保存权威策略、池、活动去重、指标聚合和待发批次。Redis 仅发布
可丢失的 `wake` 通知，收到后重新读数据库；不保存权威状态。Redis 不可用或
通知丢失不修改策略，也不阻塞业务，每秒的数据库调度仍可继续处理。

每实例最多四个发送 worker、本地队列 256 条；领取租约 30 秒，发送超时
10 秒。队列满或存储故障只影响遥测，不阻塞推理，不进入业务计费或账号冷却。
发送沿用冻结的业务代理 ID，代理无法解析时跳过，不回退直连。发送前读取
最新账号凭据并核对身份，token 和代理凭据不保存在批次中。

Analytics 使用账号 OAuth，OTLP 使用 Statsig SDK key 和 exporter UA，不携带
OAuth Bearer。两个端点均禁止重定向。数据不保存业务正文、原始响应、token、
完整请求头或代理凭据；错误使用固定本地原因码，不保存原始错误正文。

未开始发送的任务允许恢复。已经开始发送但无法确认结果的任务标记 `unknown`，
不盲目重发，因此不保证外部端点恰好接收一次。未发送批次超过 24 小时丢弃，
终态批次保留七天后清理。停止进程保留已提交任务；全局关闭通过策略代次取消
旧数据，重新开启不补发。已经发送的数据不能撤回。

公开的三个设置值是管理员意图，私有策略代次是发布围栏。发布事务在二者不
一致时拒绝出队或写入；读取及配置回调会重新读取公开设置并修复私有代次，
不能用旧实例快照覆盖新配置。代次变化同时废弃未汇总指标和旧未封存回合，
保留池、启动与线程初始化标记，因此重新开启不会补发关闭前的积压活动。

## 环境变量和只读接口

| 变量 | 行为 |
| --- | --- |
| `CODEX_TELEMETRY_ENABLED` | 留空由后台控制；`false` 关闭本实例，不能覆盖后台关闭，也不能删除其他实例数据 |
| `CODEX_STATSIG_API_KEY` | 可选 Statsig SDK key 覆盖，不通过设置或观测 API 返回 |

Compose 可在 `deploy/.env` 配置；直接运行时设置进程环境。环境变量修改需要
重建容器或重启进程，后台设置通过数据库策略和 Redis 唤醒传播。

「指纹观测 → 客户端遥测」展示最近 500 条本实例脱敏摘要，重启会清空。
这与持久化池及跨实例任务状态不同。查询不触发上游发送，遥测也不依赖
每日固定根或指纹观测开关。

`GET /api/v1/admin/openai/telemetry-observations` 复用管理员认证。

| 参数 | 可选值 |
| --- | --- |
| `account_id` | 正整数 |
| `type` | `analytics` / `metrics` |
| `status` | `queued` / `sent` / `failed` / `dropped` / `cancelled` / `skipped` / `unknown` |
| `os_family` | `windows` / `macos` / `linux` |
| `source` | `observed` / `simulated` / `mixed` |
| `page` / `page_size` | 默认 1 / 20，单页最大 100 |

响应保留 `contains_simulated` 并根据实际内容计算。新增 `os_family`、`pool_id`、
`batch_id`、`source`、`reasons`、`field_sources` 和两个子开关状态，区分
实测、模拟、混合及身份缺失、存储不可用、跳过或发送结果未知等原因。

## 升级和验证

**升级前先排空并停止旧进程，再执行新增遥测表迁移并启动新版本**，避免旧的
进程内模拟与新持久化规则混跑。各系统首次有业务时建立池，不把旧内存摘要
转成历史启动或客户端完成事实，也不批量制造历史遥测。

验证使用模拟 HTTP/WS 上游、隔离 PostgreSQL/Redis 和浏览器模拟接口，不向
真实业务或遥测端点发送请求。覆盖三系统隔离、模式组合、多次 sampling、
工具继续、重试与失败、持久化恢复、跨实例去重、领取取消及隐私字段。
