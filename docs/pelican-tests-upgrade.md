## 发布顺序

1. 停止所有旧版本应用实例及测试工作进程，避免滚动发布期间旧进程领取新任务。
2. 执行数据库迁移 `262_account_pelican_tests.sql`（应用启动时由现有迁移流程执行）。迁移取消未完成的旧糖果任务，清除租约，并结束对应批次；不会重新执行这些任务。
3. 启动新版本应用，再恢复入口流量。不要启动未包含本迁移对应代码的旧工作进程。

本次代码交付不执行部署或操作线上数据库。

## 历史兼容

- 旧糖果记录保留原有终态结果，不重新判题；历史、列表摘要及批次接口仅返回 `pelican-v1`。
- 旧批次 ID 返回不存在。复用旧幂等键会返回冲突，请为新测试生成新的键。

## Daybreak

鹈鹕测试按任务开始时冻结的账号 Blue／Red 偏好补充 `access_programs.cyber`，本次自动重试沿用同一偏好。两类诊断测试（鹈鹕和归因）独立于系统 Daybreak 总开关和分组开关；普通请求和账号连接测试不改变规则。仅普通 OpenAI OAuth 账号可自动补充，API Key 和 Codex-Engine 不扩大支持范围。共享凭据账号沿用被测业务账号偏好，并核实凭据源的实际能力。

仍需满足模型档位和真实上游目录能力：Astra／6.1 Sol 需要账号 Blue＋Red，发送 `daybreak_blue`。能力查询失败、能力不足、未识别型号或未开启所需档位时，不添加字段且继续测试；每次实际发送按现有缓存期限确认，不无限使用过期证据。失败重试不修改账号健康、计费或既有重试规则。

结果详情显示成功请求实际携带的字段或未添加原因，旧历史没有证据时显示「未记录」。字段证据保存到原有执行结果 JSON，不新增接口或数据库列。中途修改账号开关不终止当前任务，后续新任务使用新的偏好。
