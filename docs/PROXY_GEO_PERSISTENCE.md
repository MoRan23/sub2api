# 代理地域与时区维护

新增代理后，后台自动获取出口 IP、地区及 IANA 时区。服务启动时读取已保存的结果，并补齐未删除代理中缺失或无效的信息；周期扫描也覆盖导入及同步服务创建的代理，包括未绑定账号或已停用的代理。获取元数据不会改变代理的业务启用状态。

成功结果保存在 PostgreSQL 的 `proxy_geo_snapshots` 表，不再按 24 小时过期。更换应用容器、清空 Redis 或重启服务后仍可恢复；已有有效结果不会因此再次探测。升级时会核对代理当前连接配置，将旧 Redis 中的可用记录迁入数据库。

手动“测试连接”或“质量检测”会重新获取信息。同一出口查询失败时保留之前成功的地域；代理连接配置改变，或检测到不同出口 IP 时，不会借用旧出口的地区和时区。没有成功结果时，后台限速重试；成功后停止自动探测。

自动任务使用有界队列、有限 worker 和 Redis 互斥租约。PostgreSQL 写入核对当前代理配置，并按探测开始时间拒绝迟到结果；已删除代理的结果不能重新写回。数据库不可用时暂停新增自动探测，避免把暂时读不到的已保存结果当作缺失后重复获取。

这项持久化适用于已配置代理；服务器直连出口仍沿用原有的周期更新策略。信息保存在现有 PostgreSQL 数据库中，因此替换应用容器时应继续连接原数据库。

账号的 Codex turn-state 缓存开关不影响被动指纹观测。具体行为见 [Codex turn-state 说明](CODEX_TURN_STATE.md)。

## 本次验证

使用 Go 1.27.0 和 `GOEXPERIMENT=jsonv2`。全包构建及 unit 标签全包测试编译通过；代理管理、导入、Wire 清理、HTTP／WS 被动观测的定向回归通过。聚合竞态验证有 102 个顶层用例通过；最后的地域一致性修复另复跑 38 个顶层竞态用例，均无失败、跳过或数据竞争。

隔离 PostgreSQL／Redis 中的 7 项集成用例通过，覆盖旧记录迁入、Redis 丢失后恢复、并发提交、代理变更与删除、缺失补全及锁所有者校验。前端相关组件与 i18n 测试、类型检查、lint 和生产构建通过。验证使用本地模拟上游和合成数据，没有访问用户代理或发送真实收费请求；本次按变更范围测试，未重跑全仓默认／unit 测试。原始记录位于 `.git/task-artifacts/proxy-geo-passive-state/`。
