# turn-state 原因、重试及目标票据 Cookie 提交修正

基线：`dev@76d426c23`。本次不部署，不发送真实业务、采集、OAuth 或遥测请求。

## 修正范围

- 后端返回 `model_mismatch`，前端过去只映射 `collector_model_mismatch`，导致具体原因显示为“原因未分类”。兼容两种固定代码，并补充共享授权不可用的说明。
- 普通错误后的模型不再继承其他模型的 5 秒形态重试或正在采集的崩溃恢复预留。真实限流仍跨模型共享；账号跨实例单飞保留。
- 上次限流标记不能把下一次采集的超时预留提升为账号冷却。失败的 CAS 也不能提交账号冷却副作用。
- 账号 HTTP Cookie 先按物理请求暂存，成功取得合格目标票据后才提交。请求参与缓存维护时还需票据发布被接受；不参与维护的可信业务仍可学习 Cookie，Cookie 自身的授权与版本检查不变。流失败、未交付、异常票、采集模型不一致及迟到失效结果不提交。
- Cookie 提交逐项比较请求发送时的条目版本，整个候选批次原子合并。候选的删除与会话 Cookie 更新同样受准入限制；已有 Cookie 的自然到期不受影响。未绑定账号的 OAuth 流程继续使用独立临时内存池。

三系统共用 OAuth 授权，turn-state 票据、需求及代理计数仍按账号／系统／模型隔离，Cookie 仍按账号／系统／授权代次隔离。本次没有改变此隔离规则。

## 升级说明

无数据库结构迁移。统一更新旧实例，避免旧代码继续无条件保存响应 Cookie 或把采集预留写成账号冷却。既有 Cookie 没有目标票据来源记录，不能可靠追溯；本次保留到原期限，仅约束升级后的新增、替换和删除。此前已写入的冷却保守保留到原期限，避免误清真实限流。

- 实际 HTTP 传输包装器的定向竞态测试通过；同账号／系统跨代理读取已提交 Cookie，未确认的辅助响应不学习。
- 合并 Go 竞态回归通过，764 项测试及子测试、无跳过。覆盖 Responses／透传／Chat／Messages 流式与非流式入口，成功目标、异常票、失败后完成、未交付、临期同票、模型排除、维护不可用、迟到发布，以及超时／连接关闭／503 无人工延迟和真实限流保留。
