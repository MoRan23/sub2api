## V4 — final source, fixed CPU affinity and reversed middle round

Driver [run-retry-affinity-bench.py](v0.2.22/run-retry-affinity-bench.py) sets Windows process affinity to 0x55 before launching child test processes; children inherit the mask. GOMAXPROCS remains 4. Each benchmark runs for 3s. Round 1: baseline then merged; round 2: merged then baseline; round 3: baseline then merged.

## Reproduction / 复现

The final V4 code and fixtures are committed with this report. Run these commands from the repository root in **Windows Git Bash**, with Go 1.27.4 and Python 3. Use a fresh output directory and stop other builds/benchmarks while measuring. No model call or external service is required.

All three benchmark definitions already exist in baseline commit `08a02ad7f`; no test-file copying is required. The three test files in the source directory used to build the measured baseline binary match that commit's files exactly after line-ending normalization.

| Benchmark | Existing baseline test file |
|---|---|
| `BenchmarkOpenAIResponsesRetryPreparation` | `backend/internal/handler/openai_gateway_retry_preparation_test.go` |
| `BenchmarkCodexTransformRetryCPU` | `backend/internal/service/openai_codex_transform_cpu_test.go` |
| `BenchmarkOpenAIResponsesToolSchemasCPU` | `backend/internal/service/openai_request_predicates_cpu_test.go` |

The merged revision retains the same benchmark bodies and fixture builders. Its additional validation unit tests do not alter the benchmark payloads. The handler test's uncached helper calls the renamed context normalizer, but the recorded `/after` selector uses `openAIResponsesRetryPreparation.forAccount`, not that uncached helper. The affinity driver rejects a successful process exit if its log contains no benchmark result, preventing a silent `PASS` with an unmatched selector.

```sh
export GOTOOLCHAIN=go1.27.4 GOEXPERIMENT=greenteagc,jsonv2 GOMAXPROCS=4
MERGED_ROOT="$(pwd -W)"
BENCH_ROOT="$(cd .. && pwd -W)/sub2-v022-reproduction"
mkdir -p "$BENCH_ROOT/bin" "$BENCH_ROOT/logs"
git worktree add --detach "$BENCH_ROOT/baseline" 08a02ad7f

(cd "$BENCH_ROOT/baseline/backend" && \
  go test -p 2 -tags unit -c -o "$BENCH_ROOT/bin/service-baseline.test.exe" ./internal/service && \
  go test -p 2 -tags unit -c -o "$BENCH_ROOT/bin/handler-baseline.test.exe" ./internal/handler)
(cd "$MERGED_ROOT/backend" && \
  go test -p 2 -tags unit -c -o "$BENCH_ROOT/bin/service-merged.test.exe" ./internal/service && \
  go test -p 2 -tags unit -c -o "$BENCH_ROOT/bin/handler-merged.test.exe" ./internal/handler)

python docs/validation/v0.2.22/run-retry-affinity-bench.py \
  --baseline "$BENCH_ROOT/bin/service-baseline.test.exe" \
  --merged "$BENCH_ROOT/bin/service-merged.test.exe" \
  --working-directory "$MERGED_ROOT/backend" \
  --output "$BENCH_ROOT/logs/v4" --mask 0x55
```

The driver fixes affinity before spawning the test binaries, keeps `GOMAXPROCS=4`, runs both representative cases for 3 seconds and executes all three rounds, reversing the middle round. Select a mask valid for the local machine if `0x55` is unavailable, and record that difference. Output files are created exclusively; existing logs are never overwritten.

To run the original 29-case selector against separately compiled binaries:

```sh
for round in 1 2 3; do
  for variant in baseline merged; do
    "$BENCH_ROOT/bin/handler-${variant}.test.exe" \
      -test.run '^$' \
      -test.bench '^BenchmarkOpenAIResponsesRetryPreparation/(64KiB|1024KiB|8192KiB)/(1attempts|5attempts|15attempts)/after$' \
      -test.benchmem -test.benchtime=500ms -test.count=1 \
      > "$BENCH_ROOT/logs/retry-bench-${variant}-handler-${round}.log" 2>&1
    "$BENCH_ROOT/bin/service-${variant}.test.exe" \
      -test.run '^$' \
      -test.bench '^(BenchmarkCodexTransformRetryCPU|BenchmarkOpenAIResponsesToolSchemasCPU)/(1MiB|8MiB|image|text)/(image_false|image_true|1MiB|8MiB)/(attempts_1|attempts_5|attempts_15|repair=false|repair=true)/(sparse|current)$' \
      -test.benchmem -test.benchtime=500ms -test.count=1 \
      > "$BENCH_ROOT/logs/retry-bench-${variant}-service-${round}.log" 2>&1
  done
done
```

The archived V1–V3 measurements came from intermediate worktree variants, not separate release commits. V1 predates the early `pattern`/Unicode-escape-marker negative gate; V2 adds that gate; V3 also temporarily substitutes `gjson.ValidBytes(body)` for `json.Valid(body)` in `sanitizeOpenAIResponsesToolSchemas` and adds its import. V4 reverts that validator substitution. Restoring those described variants is necessary to recreate their source state; running the broad selector against final code measures final code instead.
