# 账号级 Codex turn-state 缓存

> 历史说明，已被 [当前 Codex turn-state 规则](codex-turn-state.md) 替代。下文保留旧版本设计记录，不用于配置或升级：当前票据包跨系统共享、仅用于 HTTP，本地有效期为 240 秒；原生 WebSocket 旁路票据。

此功能为常规 OpenAI OAuth 账号提供按最终上游模型隔离的 `x-codex-turn-state` 缓存与后台维护。默认关闭。跨会话、跨轮次复用属于实验策略，符合目标形态不代表模型质量得到改善。

## 全局生效模型

在“系统设置”的网关设置中配置 Codex turn-state 生效模型名单，默认包含：

- Astra：`gpt-6-astra`
- Sol：`gpt-5.6-sol`
- Terra：`gpt-5.6-terra`

只有账号开关已开启、且最终上游模型在名单内，才会从正常响应保存可复用状态、注入缓存或启动后台采集。名单按账号映射及上游归一化之后的完整模型 ID 精确匹配，不按模型家族扩展；例如 `gpt-5.6-sol-wm` 不因 Sol 在名单中而自动生效。

名单外的模型继续正常转发，账号页仍可查看正常响应中实际收到的状态形态，不会为缺少状态反复采集。将名单保存为空会暂停所有模型的缓存维护；旧版本未配置该项时使用上述默认值。管理接口 `GET /admin/settings` 返回 `codex_turn_state_models`，`PUT /admin/settings` 省略该字段时保留原配置，显式传入 `[]` 才会清空。

修改名单不打断已发送的业务请求。移除的模型停止新注入及采集，旧任务结果不能重新发布；再次加入时仍须通过当前配置、凭据和有效期检查。

## 开启与账号类型

在账号创建或编辑页开启 Codex turn-state，选择账号类型及可选的独立采集代理。

| 配置 | 行为 |
| --- | --- |
| 自动 | 使用账号已有套餐信息；无法确定套餐时暂停采集和注入，可手动选择类型 |
| 个人 | 接纳 292 字符、10 个密文块；312 字符、11 个块触发对应旧状态失效和续采 |
| Team / Business | 接纳 332 字符、12 个密文块；356 字符、13 个块触发对应旧状态失效和续采 |
| 未选择采集代理 | 仅从正常业务响应学习，不发送额外采集请求 |

自动分类识别账号已有的套餐值，包括 Business Premium 的 `self_serve_business_prolite`（Team / Business）及 Pro 5x 的 `prolite`（个人）。未知套餐不会从 token 长度反推，可由管理员手动选择分类。

这些数字是字符串长度，不是 HTTP 状态码。长度分类来自样本经验；程序还检查 Base64url、Fernet 封装结构和签发时间，但不解密内容，也无法验证未知密钥的签名。Fernet 固定开销为 57 字节，密文按 16 字节分块，再经 Base64url 编码；仅凭长度不能证明内容存在“降智开关”。

Spark 影子账号继承真实凭据母账号的配置和状态。缓存按凭据母账号、凭据或配置代次及最终上游模型隔离，不在不同账号或模型之间共享。

## 正常请求优先

首次使用模型时先正常转发业务请求。业务响应已取得符合目标形态的状态，就使用该状态，不额外采集。响应头及 `response.metadata.headers` 均可提供候选值；未成功交付、已被失败切换丢弃的响应不发布缓存。

开启功能且存在有效缓存时，始终用缓存覆盖实际出站 turn-state。HTTP 请求头和已存在的正文状态保持一致；WebSocket 在每轮 `response.create.client_metadata` 使用该轮模型的状态。原客户端状态与 continuation 仍须先经过来源校验。

没有有效缓存时，业务请求继续正常转发：不等待后台采集、不因缺少状态阻断、不重放用户请求。存储不可用也回退到原转发行为，不依赖本地陈旧缓存继续注入。

## 后台维护策略

| 项目 | 本地策略 |
| --- | --- |
| 有效期 | 从状态签发时间起 60 分钟 |
| 提前续期 | 到期前 5 分钟 |
| 扫描间隔 | 30 秒 |
| 活跃模型范围 | 最近 30 分钟有真实业务请求的模型 |
| 单次采集超时 | 20 秒 |
| 失败重试间隔 | 至少 180 秒；429 尊重更长的 Retry-After 或账号冷却 |
| 并发限制 | 有界队列、每实例最多 4 个 worker、跨实例每凭据账号最多一个采集任务 |

以上时间是本项目的维护策略，不是上游公布的有效期。重复返回同一状态不会延长寿命，较旧响应不会覆盖较新状态。空闲模型停止续采；恢复使用时仍先尝试正常业务请求。

后台采集只使用账号指定的独立采集代理，业务继续使用原业务代理。采集代理不可用时报告原因，不自动切换出口。每次采集发送一条使用当前 OAuth 凭据和目标模型的短请求，不携带业务正文、原状态或 continuation。它使用独立请求身份，不占用每日流式根，不触发模拟遥测或下游用户计费；上游仍可能将其作为一次请求计量。

401 或 403 暂停后台采集，直至凭据或配置变化。正常业务请求取得新状态会取消同范围的排队或在途采集。迟到的采集结果或异常响应不能覆盖新状态。

## 生命周期与排查

开关、账号类型、采集代理或有效 OAuth 凭据变化会使旧运行态失效；普通用量更新不影响配置代次。关闭后停止新的注入和采集，取消在途采集，并拒绝旧代次结果。已发送的轮次不会中断；需要切换握手方式的旧 WebSocket 连接会在轮次结束后退役，由客户端重新连接，不重放已发送请求。

运行态保存于独立 PostgreSQL 表，token 使用现有 `SecretEncryptor` 加密；Redis 用于采集互斥与取消通知。重启后恢复仍有效的持久化状态。代理引用计数与删除保护包含采集代理。导入和导出通过代理映射键迁移配置，不携带运行态、token 或配置代次。

管理员可在账号列表的“更多”菜单选择“查看 turn-state 状态”，查看各模型的状态、目标形态、来源、剩余有效时间、最近采集及脱敏错误。只读接口为 `GET /admin/accounts/:id/codex-turn-state`（标准 API 前缀下为 `/api/v1/admin/accounts/:id/codex-turn-state`），不返回完整 token。指纹观测显示实际出站状态长度、来源、替换动作、最终模型和续采原因，不记录可恢复的 token 片段。

账号管理表格默认显示 turn-state 列，以固定三行“状态圆点＋模型名”展示，更多模型标注数量，点击可打开完整详情；可通过列设置隐藏。绿点表示最近观测符合目标形态且校验通过，红点表示扩展形态或明确的封装异常，灰点表示无数据、无法确定、过期或读取失败；没有观测时才参考仍有效的缓存。悬停及详情可查看长度、来源与时间，观测摘要不等同于可注入缓存。关闭缓存及指纹观测也可显示这些圆点，影子账号共享请求发送时已确认的凭据母账号摘要。自动刷新保留同一账号的既有内容，收到结果后更新颜色，刷新过程不显示“正在加载”或“本实例尚无观测”文字，避免行高变化；刷新失败保留模型名并显示灰点。查询不会触发采集。列表使用 `GET /admin/accounts/codex-turn-state?account_ids=1,2` 批量读取，每批最多 200 个账号，并对共享母账号去重。

账号页的轻量 turn-state 摘要独立于账号缓存开关和全局指纹观测开关，两者都关闭时仍会从正常业务响应记录实际收到的状态长度、封装形态、来源和时间。最终模型不在全局维护名单内也可显示。仅观测不会因此注入状态、建立可复用缓存或发送采集请求。完整的请求指纹明细仍由原指纹观测开关控制。

摘要按凭据母账号及最终模型保存于当前实例内存，最多保留 4096 组，不受指纹请求明细 500 条容量限制；不保存 token、密文、hash 或可恢复片段。切换指纹观测不清空摘要；重启实例会清空，多实例不会共享。接口通过 `observation_scope: "instance"` 和 `observations` 返回轻量摘要，`observation_enabled` 表示该摘要能力可用，不再表示指纹观测开关；持久化缓存仍在独立的 `models` 字段中。没有历史记录时列表显示灰点，详情提供空状态说明。单次响应未返回状态或请求失败不会抹掉最近真实观测，也不能据此认定该模型不支持状态。

响应观测将封装形态与缓存准入分开显示：通过 Base64url 和 Fernet 结构检查的 332 / 12 块、356 / 13 块分别显示 Team / Business 目标与扩展形态；同时显示未知套餐、套餐不匹配、过期、未来签发时间等校验原因。识别封装形态不改变账号套餐，也不代表该值可注入或模型质量得到改善。历史观测不会重新解析或补写。

若未注入或未续采，依次查看账号开关、最终上游模型是否在全局名单内、自动套餐识别结果、是否已有真实业务请求、状态是否过期、是否选择采集代理，以及状态页中的代理、授权或退避原因。无需采集时可不配置采集代理，仅使用业务响应学习。
