# add-openai-compatible-prompt-audit

在不改变现有内容审核行为的前提下，新增独立的 OpenAI 兼容 Qwen3Guard 提示词安全审计模块，完整支持异步审计、同步阻断、持久任务队列、事件工作台与独立管理页面。

阅读顺序：`proposal.md` → `source-baseline.md` / `source-feature-map.md` → `design.md` → 三个 `specs/*/spec.md` → `implementation-guide.md` → `tasks.md` → `verification.md`。

## 关键词拦截复核

- 关键词输入框支持直接按回车逐行添加；编辑时保留换行和空白，保存的列表仍去除空项、首尾空格及大小写重复项。
- 新的关键词拦截事件保存当次实际触发阻断的首个配置关键词，管理员可在详情的“审计摘要”和“具体风险”中查看“命中的关键词”。沿用现有按配置顺序匹配、首次命中即阻断的规则。
- 命中词复用现有事件 JSON 存储，无需数据库迁移。关键词拦截的客户端错误消息会附上实际命中词，例如 `提示词包含禁止内容，请调整输入后重试（命中关键词：".gov."）`；状态码和错误码 `prompt_keyword_blocked` 保持不变。HTTP（包括流式请求的前置拒绝）及 WS 错误帧均使用该消息。旧事件只记录了哈希时，详情显示“未记录”。

## 关键词拦截 Key 白名单

- 在关键词规则下先搜索用户，再选择该用户的 API Key 并加入白名单。每条记录精确绑定用户 ID 和 Key ID；同一用户的其他 Key 不豁免。
- 白名单只跳过本模块的关键词拦截，Guard 审核及其他风控仍按原配置执行。删除白名单项并保存后，该 Key 恢复关键词检查。
- 配置字段为 `keyword_whitelist_keys`，例如 `[{"user_id": 7, "api_key_id": 42}]`。服务端保存时校验 Key 确实属于该用户；配置不保存 Key 密钥正文。字段缺失或 `null` 保留现有设置，显式空数组清空；旧配置默认空白名单。无需数据库迁移。
