# OpenAI OAuth 三系统身份与会话根

常规 OpenAI OAuth 凭据账号分别保存 Windows、macOS、Linux 三套 UA、UUIDv4 `installation_id` 和长期同步根。Spark 使用母账号配置。API Key、setup-token、PAT、Agent Identity 及其他平台不使用这套资料。

每个系统现在还需要分别授权，有安装身份不代表具有可用授权。升级只把原凭据保留到当前默认系统，其他系统等待授权；调度不会借用另一系统的凭据。见 [三系统独立授权与升级说明](OPENAI_OS_OAUTH_AUTHORIZATION.md)。

## 升级与持久化

升级前应排空旧服务进程并停止旧身份写入，再启动新版本；不要让新旧身份规则混跑。数据库迁移 `248_openai_oauth_os_profiles.sql` 新建系统身份表，`249_openai_oauth_daily_os_roots.sql` 新建具名每日根表。

启动补全每页读取 100 个账号，逐账号加行锁，与请求入口的幂等补全使用相同事务。旧 UA 可识别时保留它和原合法安装 ID，绑定该系统为默认系统；未知 UA 默认 Windows，保留合法 ID 并生成 Windows UA。其余两套仅在缺失时生成。新建及导入的新账号生成本地身份，以首个明确授权系统为默认；旧调用未指定系统时默认 Windows。更新已有账号保留已保存身份。

安装 ID、UA 和长期同步根保存到数据库后才能用于请求。资料补全失败时返回脱敏错误，不发送临时生成的身份。账号普通编辑、批量更新、令牌刷新及旧快照写入不能覆盖受管资料。旧单值 UA 和安装 ID 保留为默认系统的兼容镜像。

## 选择与开关

业务请求依次使用以下线索选择系统：

1. 原始 UA 的系统段；不根据终端名称判断。移动系统或冲突系统段视为未知。
2. 本轮独立 `environment_context` 的明确系统字段或工作目录线索：Windows 盘符／UNC、`/Users/`、`/home/`。通用目录和单独 shell 名称不足以分类；引用、技能、工具说明与历史环境不参与识别。
3. 账号默认系统。

识别不修改正文的路径、shell、sandbox 或权限声明。现有时区转换规则保持不变。身份归一、固定安装 ID、每日固定根仍分别遵守原开关；强制 Codex 客户端模式决定客户端家族与版本，系统环境取所选配置。

同一请求的系统、接收日期和每个账号的出站身份被固定。重试不因跨午夜切根；切换账号后取新账号对应系统资料。WebSocket 在首次上游握手前固定身份及根，物理连接内保持一致。新请求的新连接按其接收日期选根。installation 缓存、子线程映射和连接身份区分系统。

后台独立任务使用账号默认系统或任务已绑定的系统授权。业务遥测沿用关联请求的实际身份。独立 turn-state 采集使用需求所属系统的授权，保留专用请求和独立会话，不携带业务 continuation，不进入每日固定根，也不因本改动新增安装 ID 携带行为。

## 每日根和长期根

业务日使用 Asia/Shanghai。开启每日固定根时，每系统各一条流式根和一条同步根，共六条；流式根不再随机选择。旧三条流式根依次绑定 Windows、macOS、Linux；旧同步根绑定账号默认系统，补齐另外两个系统。

关闭每日固定根时，同步请求使用三个系统各自的长期同步根；旧长期同步根保留到默认系统。旧 affinity 数据保留但不再用于常规 OAuth 的新分配。子线程仍基于所选根映射，不清空 Redis；迁移后根发生变化的旧会话会获得新的子线程，已发送请求继续使用其快照。

管理查询只读，返回具名 `os_roots` 并保留旧字段投影。页面按系统展示两类根，指纹详情展示实际系统和识别来源。

## 管理与导出

创建页展示三套待生成配置；保存后编辑页显示三套只读 UA 与安装 ID。安装 ID 可按系统单独重新生成，其他系统与会话根保持原值。旧重生成接口不传 `os` 时操作默认系统。Spark 页面显示母账号继承关系。

常规 OAuth 账号支持单账号导出 Codex `auth.json`；导出不包含系统身份、根、代理或 turn-state，详见 [auth.json 导出说明](OPENAI_CODEX_AUTH_EXPORT.md)。
