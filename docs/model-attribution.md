# 降智检测

管理员在侧边栏「降智检测」配置 ModelTrace 服务地址、探针模型及高低级白名单。
迁移 `263_model_attribution.sql` 初始关闭自动检测，默认探针模型为 `gpt-6-astra`。
服务地址及两份非空白名单配置完成后才能开启。模型选择器支持手动输入具体模型 ID。
「测试连接并获取候选模型」只查询指纹库；实际归因探针会消耗上游账户额度。

## 检测和分组

- 每个符合条件的 OpenAI OAuth 实体账户每 10 分钟进入一轮队列；扫描间隔 30 秒。
- 分组可继承全局配置，也可启用独立配置。按 `account_groups.priority` 升序选择首个独立配置，同优先级按分组 ID 排序。
- 探针模型也是期望模型。三条独立探针依次使用真实 OAuth 账户、账户代理及默认授权环境执行，绕过业务白名单与模型映射，不提供工具、不自动重试、不修改健康状态、不产生下游用户扣费。
- 停用、关闭调度、过期、删除、自动透传和共享凭据的影子账户跳过检测。账户列显示跳过原因。
- ModelTrace 通过 `GET /api/banks`、`GET /api/challenges`、`POST /api/analyze` 提供模型库、题目和概率。仅发送题目回答和期望数量，绝不发送账户令牌。
- ModelTrace 未收录期望模型时，不发送模型探针。服务不可用、回答未全部有效、概率无效或最高概率并列都记为异常。

账户列表「归因测试」列分别显示活动任务与最近结束的结果，支持单账户和批量立即测试。手动测试与自动测试共用相同队列、去重与名单切换规则。

## 新 OAuth 账号首测

「降智检测 → 新 OAuth 账号首测」提供归因、鹈鹕两个独立开关（默认开启）及共用首测模型（默认 `gpt-6-astra`）。归因首测还要求全局检测已经配置并启用；鹈鹕首测独立于全局检测开关。

设置仅影响保存后新建或导入的 OpenAI OAuth 实体账号，不补测旧账号。创建时保存首测选择，每 3 秒入队；停用、关闭调度、过期、删除、自动透传及影子账号跳过。入队前再次检查当前开关，已手动测试的账号不额外重复首测。两种测试消耗上游额度，不自动重试。

归因首测使用首测模型作为期望模型，名单仍按分组规则选择；后续十分钟周期使用原全局 / 分组探针。关闭归因首测只取消这一次即时测试，不关闭周期检测。首测和周期模型不同会分别建立有效判定基线。

迁移 `264_new_account_tests.sql` 新建创建事件表。账号、首测事件同事务保存；两种测试的入队与事件消费也同事务提交，多实例、重启及历史清理都不重复触发。每个账号仅一条事件，不保存令牌或回复，物理删除账号后级联清理。

## 白名单规则

最高概率模型 ID 必须与探针模型 ID 完全一致才算通过，不另加概率阈值。

| 当前结果 | 最近有效结果 | 行为 |
| --- | --- | --- |
| 通过 | 无 | 应用高级白名单 |
| 通过 | 通过 | 不修改 |
| 通过 | 不通过 | 应用高级白名单 |
| 不通过 | 任意 | 应用低级白名单，内容相同不重复写入 |
| 失败 / 异常 | 任意 | 不修改，不覆盖有效判定 |

配置版本或有效分组策略变化后，下一次有效结果同步新名单。OAuth 普通刷新保留基线，重新授权或更换探针模型后重新建立基线。

更新只替换 `credentials.model_mapping` 中 `key == value` 的白名单条目；别名、通配符及冲突键的原映射保留。这些映射继续按现有业务路由规则提供访问。

结果应用、JSONB 字段更新、有效判定和调度缓存 outbox 事件处于同一事务，不覆盖其他凭据字段。回写前重新核对配置、授权代次、分组及模型映射；检测期间的配置或人工修改使结果过期，仅保留记录。未提交的名单变更不记为同步成功。

## 队列和存储

- PostgreSQL 唯一活动任务索引与事务锁保证单账户不重叠、全局最多同时运行 3 个账户，支持多实例。
- 运行租约 45 秒，每 10 秒续期；续期/校验有 5 秒上限，整轮最长 10 分钟。
- 过期任务终止并记录中断/超时，不重新发送已运行请求；停机期间的周期不补发。
- 每账户只保留最近 100 条已结束任务。有效判定独立存储，历史清理不影响恢复。
- 不持久化原始回答或 OAuth 令牌。详情包含配置快照、概率、有效性诊断、用量和名单变更。
- 配置保存使用版本校验，冲突返回 HTTP 409。

管理员 API 前缀为 `/api/v1/admin/model-attribution`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / PUT | `/config` | 读取 / 按版本保存配置 |
| POST | `/models` | 检查连接及查询候选模型 |
| POST | `/jobs` | 为 `account_ids` 创建去重任务 |
| GET | `/jobs` | 分页查询，可传 `account_id` |
| GET | `/jobs/:id` | 结果详情 |

## 本地验证

使用模拟 ModelTrace、模拟上游及独立 PostgreSQL/Redis 容器，没有真实模型或支付请求。

- Go：配置选择、跳过条件、三探针链路、数值验证、上游失败、取消/超时、绕过名单、既有鹈鹕传输/OAuth 刷新回归。
- PostgreSQL/Redis：首次通过、通过/失败转换、异常恢复、配置更新、分组优先级、令牌刷新、授权/人工变更防护、事务回滚、缓存 outbox 生效、并发去重、三任务容量、租约过期、不重放、100 条保留、重复迁移。
- 前端：50 项相关 Vitest、类型检查、i18n 完整性、生产构建、改动文件 ESLint；实际 Chrome 模拟接口检查配置页、侧边栏、账户列、详情、任务创建和鹈鹕 iframe。
- Go vet 和 Windows/Linux 服务端构建通过。
