# Codex turn-state 缓存与观测

账号创建或编辑页可开启 Codex turn-state 缓存，选择个人、Team / Business 或按已有套餐自动识别，并设置有序的独立采集代理列表。默认关闭；仅支持常规 OpenAI OAuth。Spark 影子账号继承凭据母账号的设置和状态。未知套餐暂停缓存注入与采集，可手动选择分类。

全局生效模型名单默认是 `gpt-6-astra`、`gpt-5.6-sol`。`gpt-5.6-terra` 已移出默认名单，已保存的自定义名单不会被覆盖；管理员仍可手动加入其他模型。名单按最终上游模型 ID 精确匹配。

## 获取与续期

- 首次实际发出的合格 Lite HTTP 业务请求为生效模型建立独立采集需求，不等待业务完成。非 Lite 业务保持原协议及账号原代理，仍可自然学习成功交付且成功结束的目标响应，但不维持 Lite 采集活动。
- 活跃模型取得满足需求的目标后，至少 **30 秒**继续采集；这个成功刷新时间持久化。无状态、无效封装和套餐不匹配不能发布票据包。
- 开启缓存时，最近 30 分钟内、当前凭据且成功交付的异常业务历史可触发采集。历史摘要不保存 token，正常历史不能变成可注入缓存。
- 所有套餐的本地有效期统一为签发后 **240 秒**，到期前 **30 秒**续采。重复收到同一状态不延寿；续期结果仍位于临期窗口时继续重试。采集未取得新目标时，仍有效的旧缓存继续使用。这是本项目的本地策略，不是已验证的上游有效期。
- “本次响应未取得目标形态”、目标仍临期和“采集响应模型不一致”在结果处理完成后至少等待 **5 秒**。连接、发送、超时、5xx 或流内普通错误不增加人为退避，清除本次预留后由每秒调度重新安排；单个 worker 不循环发送。普通错误不继承 overload 或临时错误退避。429 遵守 Retry-After 和账号真实限流冷却；401 / 403 暂停至凭据或配置变化。
- 独立采集只维护最近 30 分钟实际发出合格 Lite HTTP 业务的模型，采集不延长这个窗口。“最近业务”与“最近符合采集条件业务”分别记录；准备请求、非 Lite、原生 WS 和内部辅助请求均不延长后者。

采集与正常业务并行。已有异常需求或临期续期不等待业务请求结束，业务开始也不取消采集；业务返回同一临期 token 时继续续采。仍保留每凭据账号最多一个采集任务、限流退避和配置代次保护。5 秒形态重试间隔及正在采集的超时预留只约束对应模型，不能变成其他模型的账号冷却；只有真实限流冷却跨模型共享。普通传输错误清除预留后恢复可调度，不保证同步重发，实际发送仍取决于每秒调度、空闲 worker 和账号单飞锁。并发结果按缓存内容与版本 CAS 校验，采集仅更新排队或退避状态不会使业务缓存快照失效；重复异常业务不会挤掉较新的合格采集结果，迟到异常和采集结果不能覆盖业务新取得的目标状态。

三系统共用账号 OAuth 授权，**turn-state 票据包、采集需求和代理轮换计数按“凭据母账号＋最终模型”共享**。每个包原子保存票据、Cookie、实际协议、出票代理及其连接配置代次；仅同协议业务可复用，不增加协议分区。OS 不再参与缓存键；三系统 UA、installation ID、会话根及遥测身份仍独立。状态详情展示共享缓存，系统筛选只影响真实请求观测。

HTTP 业务使用正常缓存出站后，成功交付的合法异常响应会废除这次请求使用的旧缓存并建立采集需求，一次即可触发。期间其他请求取得的新缓存受到保护，重复回调不会重复失效。新需求立即排队，但实际采集仍遵守已有失败退避和账号冷却；旧的成功刷新等待不会阻止异常后的补采。

短暂存储错误或连续 CAS 冲突时，HTTP 业务的异常失效进入有界的待发布队列，按原请求的缓存身份重试失效与需求写入，不能清除并发取得的新缓存。队列最多 4096 项，每秒处理最多 32 项，每批预算 3 秒；过期、原业务发送满 30 分钟或配置不再适用后停止补偿。队列只在本进程内保存必要的私有比较证据，不保存响应 token 或业务正文，也不能用于注入；尚未成功落库的项在重启后不恢复，已落库需求仍由 PostgreSQL 恢复。

修改采集代理列表时，仅保留绑定出口仍被允许、连接配置代次一致的有效包；撤销旧尝试，新结果从新列表第一条开始计数。代理改名不使包失效，协议、主机、端口或认证配置改变会推进连接代次。停用、过期、删除或移出允许配置的代理不再用于对应包。单账号编辑与批量配置使用相同规则。

账号级“使用出票代理”默认开启，旧账号和未包含此字段的新建请求保持开启。开启时 Lite 业务复用包会同步使用包内冻结的出票代理；关闭时仍注入符合协议的票据和 Cookie，业务使用账号原代理（未配置代理则直连）。Spark 继承凭据母账号的开关。该开关不修改账号的 `proxy_id`，也不改变独立采集代理。

先冻结原本的协议决定、开关及具体业务出口，再生成时区、系统身份、TLS 和关联遥测；业务身份、每日根、线程、回合及 `prompt_cache_key` 沿用原规则。缺包、协议不匹配或包的来源代理不可用时，使用账号原代理无票继续。发送前才发现失效时，从原始输入完整重建一次原代理请求并保留原协议决定；已经发送的业务不因此重放。同账号同模型的重试保留快照及开关选择，换账号或模型重新选包。切换“使用出票代理”不会清空已有包、改变其到期时间或重置采集，新请求按新值选路；旧客户端编辑时省略此字段会保留已有值。正常发布新包不使旧请求改选出口；明确失效的旧包通过持久化失效水位拒绝复用，即使随后发布新包也不会复活。开启时保证的是同一代理连接配置，不能保证第三方动态代理背后的公网 IP 恒定。

每次采集使用当前 OAuth 凭据、最终模型、账号默认系统身份和指定采集代理，向 Responses 接口发送一条独立短请求，超时 **12 秒**。采集不使用业务正文、旧 turn-state、旧 Cookie 或 continuation，不进入插件转发、模拟遥测、每日会话根或下游计费。采集是上游模型请求，可能消耗账号额度。

采集模板参考 `ranxi2001/sub2api@f69b681543999e9dd28575bb2e2bc5767066ccac`：每次新建 UUID session，用户输入 `ping`，指令要求仅回复 `pong` 且不调用工具，声明不执行的 `codex.noop`。启用 Lite，设置 `stream: true`、`store: false`、`parallel_tool_calls: false`、`reasoning.context: all_turns` 及 encrypted content include，不指定 reasoning effort。采集连接不跨尝试复用；账号授权、默认系统 UA、TLS 模板及独立请求标识由本项目提供。只有明确完成、合法目标及模型证据通过验收才能发布，累计响应读取上限 1 MiB；完成事件后的失败也拒收。该模板和采集 session 不注入用户业务。

HTTP 429 和 SSE 失败事件中的结构化错误码 `rate_limit_exceeded` / `insufficient_quota` 均记为采集限流，沿用账号级退避。SSE 限流保留真实 HTTP 状态，不从错误文本猜测；重试遵守响应头 Retry-After 及账号已有冷却。失败响应中的 token 不发布为缓存，已有有效缓存和脱敏观测按原规则保留。

独立采集还校验成功响应的 JSON 模型声明：优先 `response.model`，缺失时取顶层 `model`。明确不同于最终出站模型或同次响应前后声明冲突时，不接纳候选票据、不结束需求，显示“采集响应模型不一致”。仅接受已有明确别名，不通过删日期或 `-latest` 猜测；缺少声明显示“未返回”，继续按原票据规则判断。限流、认证和流失败优先。此校验不改变业务自然学习准入，也不重放业务。模型不一致本身不改变代理计数；同次响应存在有效异常形态时仍按原目标优先、三次轮换规则处理。

未配置采集代理时仅从业务响应学习；采集代理不可用时显示失败原因，不回退到业务出口采集。业务没有适用的完整包时照常经账号原代理转发，不等待采集、不阻断、不重放，也不把旧 Cookie 带到其他出口。

## 多代理轮换

采集代理列表的顺序就是轮换顺序。每个凭据母账号、最终上游模型独立保存当前代理与异常累计次数，首次从第一条开始。只有一次成功完成的独立采集返回经封装、时间及套餐校验的个人 312 / 11 块、Team / Business 356 / 13 块，且没有有效目标候选时，才累计一次；一个请求中的多个异常候选也只计一次。业务响应的异常不计入代理次数。

当前代理累计第三次有效异常后切到下一条并归零，末尾回到第一条；下一次仍遵守结果处理后至少 5 秒及更长的真实限流冷却，不立即额外发送。超时、连接失败、无状态、无效封装、套餐不匹配等结果既不增加也不清零，429 仍退避，401 / 403 仍暂停。网络故障不会触发跳过代理。仅有一条代理时继续使用该代理，每满三次重新计数；空列表表示仅自然学习。

业务或采集取得满足需求的目标状态后，清零该模型计数并保留当前代理供下次使用。相同临期 token 没有完成续期时不清零；空闲结束需求时保留代理与计数，恢复活跃后继续。轮换位置和计数保存在 PostgreSQL，重启与跨实例不会重置；每次采集的私有尝试标识阻止重复回调或迟到结果重新计数、切换代理。

自动轮换只更新运行态，不改变配置代次、不清除有效缓存，也不突破必要重试间隔。管理员增删代理或调整顺序时，更新配置代次、撤销旧尝试，从新列表第一条重新计数；正常包按上一节规则保留，异常需求继续并保留必要退避。

账号配置新增 `collector_proxy_ids` 有序数组。旧 `collector_proxy_id` 仍可读取为单元素列表；显式数组优先，`[]` 表示清空。新写入使用数组，已有多代理账号拒绝仅用旧单值字段覆盖。列表中的每条代理都受到引用计数和删除保护。导出使用 `codex_turn_state_proxy_keys`，导入按顺序映射且兼容旧单键；映射不完整时该账号导入失败，运行态和计数不参与迁移。

## 观测与页面

HTTP 轻量观测独立于缓存开关和指纹观测开关，每模型保留本实例最新实际返回的状态摘要。HTTP 业务与独立采集均可更新摘要，详情标明请求来源及响应头 / metadata 载体。没有返回状态的请求保留原摘要和原时间。重启会清空这些本实例摘要；已加密保存的缓存和采集需求仍在数据库中。

摘要按真实发送时确认的凭据代次隔离。替换凭据后不展示旧凭据的红绿状态，旧请求迟到也不能覆盖新凭据摘要。修改个人／Team 分类后，单账号及批量接口依据观测时已验证的封装重新匹配当前分类；不从长度反推套餐，不把当时无效的状态变成有效状态，也不改变历史观测时间。

账号列表优先按生效名单显示“状态点 + 模型名”，最多 5 行；不足 5 行时，其他模型产生实际观测后动态补入，不留占位行。超过上限的模型在详情查看。独立采集缓存的以下生命周期提示优先于历史观测：仍可用但将在 30 秒内过期时显示黄色；已经过期，且后台明确判定该模型超过 30 分钟无业务而停采时显示灰色。列表本地时钟每 5 秒更新。悬停可查看具体原因。其余情况依据最新观测；没有观测时参考当前有效缓存：

- 绿：符合对应套餐的目标形态。
- 红：已观测到对应套餐的有效扩展形态。
- 灰：没有状态、无法分类或无法可靠判断。

缺缓存不会自动显示红色；已知异常正在重试时仍为红色。刷新期间保留内容和颜色，收到新结果后更新。弹窗桌面端左列缓存、右列最近观测，小屏上下排列；打开时每 5 秒刷新。“最早可重试时间”不是保证发送时间，仍受采集单飞、队列和账号状态约束。业务在途不再显示“等待业务请求完成”。采集暂停不代表仍有效的缓存不能使用。

除上述黄色临期／灰色空闲过期提示外，状态点表示最近观测的形态，不能直接当作缓存可用性：如果仍有正常缓存，但最近业务响应是 312 / 356，列表仍可显示红色。业务观测中的出站长度来自该物理请求的实际请求头／正文；长度 0 表示该请求没有携带 turn-state。收到异常响应头也不等于满足采集触发条件，HTTP 失败、未成功交付或被丢弃的响应可以留在轻量观测中，但不会建立采集需求。

右侧显示这条历史观测对应请求的发送时间、注入动作、缓存来源、未注入原因和业务交付结果，不与左侧最新业务时间拼接。独立采集的出站 0 显示为“未携带（独立采集）”，业务出站 0 显示为“未携带”；独立采集本身不携带旧状态。关联详情可查看为诊断单独生成的观察 ID、实际注入快照的版本及原到期时间，不公开运行态锁、凭据或配置代次。旧摘要缺少这些字段时不推测补齐。

采集详情按固定错误类别显示原因和排查提示，区分连接失败、空响应、响应流读取失败、上游流内失败、响应未完成、事件过大、HTTP 请求被拒绝和上游服务异常。代理认证、代理不可用、超时、限流及鉴权或访问拒绝分别说明；连接失败本身不能证明代理并发不足。账号不可采集时区分状态非正常、调度关闭和账号过期。相同的采集原因与最近错误合并展示；不同的历史错误标明为上次采集错误。已有通用“采集失败”记录无法追溯细分类别，下次采集后更新。接口与页面只使用固定的脱敏类别，不展示原始错误、代理地址、凭据或响应正文。

新的网络诊断进一步区分 DNS、连接拒绝／关闭、TLS、可识别的代理认证／隧道失败，以及连接、TLS 握手、等待响应头超时。分类来自类型化错误、传输阶段及依赖的少量精确固定错误模板，不按任意错误文本猜测。总截止时间到达时保留已知阶段及 SSE 限流原因；无法识别时显示通用失败。采集上限为 12 秒，未取得目标、目标仍临期及模型不一致使用 5 秒重试间隔，其他普通错误不增加人为等待。实际发送前再次检查账号是否正常、可调度且未到期。

安全日志 `openai_codex_turn_state_observation_completed` 记录同次请求的关联 ID、发送与观测时间、实际出站长度、注入快照版本和交付标记；`openai.codex_turn_state_collector_transport_failed` 记录采集耗时、固定阶段与错误码。日志均不记录 token、可恢复片段、哈希、代理凭据或错误原文。没有状态的业务响应不覆盖页面上的旧观测，但仍可用其独立完成日志核对出站注入。

每模型详情还显示当前／下次采集代理、最近尝试代理，以及该代理异常累计 0 / 3、1 / 3、2 / 3。累计次数不代表所有请求失败次数；第三次有效异常完成轮换后，新代理从 0 / 3 开始。账号列表继续只显示状态点与模型名。

包详情另外显示适用协议与出票代理，并只读检查绑定代理是否仍可用；请求观测显示该次实际协议、实际代理及出口来源（账号、票据包或独立采集），不能用当前采集代理反推旧包或业务的出口。关闭“使用出票代理”时，即使注入票据，出口来源仍显示为账号，出票代理单独保留。Cookie 诊断来自实际 HTTP 发送边界的最终请求头，仅记录名称、数量、来源及到期信息；未到发送边界显示“未发送”，旧记录缺证据显示“未知”。“已到发送边界”不保证网络写入或交付成功，票据长度不能证明携带了 Cookie。

## 账号连接测试中的响应摘要

账号管理的“测试账号连接”弹窗在 OpenAI 文本常规请求和原生压缩测试结束时显示上游实际返回的模型；没有返回模型字段时明确显示“未返回”，不以请求模型代替。Chat Completions 测试读取响应的 `model`，Responses 测试读取响应的 `response.model`（兼容顶层 `model`）。

常规 OpenAI OAuth 还显示响应 turn-state 的实际字符数、账号目标长度和匹配结果。Spark 使用凭据母账号的套餐及手动分类。此展示不依赖缓存、指纹观测开关或生效模型名单：个人目标为 292 字符，Team／Business 为 332 字符；目标显示绿色，对应套餐的有效扩展形态 312／356 显示红色，未返回、未知套餐、非法封装或时间校验失败显示灰色及原因。

候选只读取实际上游响应头 `x-codex-turn-state` 和 `response.metadata` 事件的 `headers`，不扫描生成文本。多个候选沿用目标优先规则；仅长度相等但封装或时间无效不会判定符合目标。结果通过测试 SSE 的 `response_info` 事件返回脱敏摘要，不返回 token、密文或哈希，不发布缓存、不建立采集需求，也不计入真实业务观测。形态匹配独立于连接测试成功与否，不能证明模型质量。

## 存储与升级

迁移 `245_openai_codex_state_credential_epoch.sql` 初始化私有凭据代次；`246_openai_codex_state_demand.sql` 增加持久化需求、采集阶段和历史消费水位；`247_openai_codex_state_collector_rotation.sql` 保存按模型的采集代理、异常计数、最近尝试代理及私有尝试标识。沿用现有迁移机制应用。普通用量更新不会使缓存失效；凭据或缓存配置变化受行锁和版本保护。私有代次、运行态和 token 不参与账号导入导出。

PostgreSQL 是缓存权威来源，Redis 用于跨实例互斥、取消和配置激活通知。每实例最多 **16 个采集 worker**，待处理队列 **128**，每个凭据母账号跨实例最多一个采集任务（跨系统、跨模型）。队列满或锁占用不丢弃持久化需求。存储不可用时恢复原业务行为，不依赖旧本地缓存继续注入。

状态接口 `GET /admin/accounts/:id/codex-turn-state` 及批量接口仅返回脱敏摘要。模型状态增加 `cache_available`、`collection_status`、`collection_reason`；观测增加 `request_source`（`business` / `collector`），与 `response_source`（响应载体）分开。多代理状态顶层返回 `collector_proxy_ids`，每模型返回 `collector_proxy_id`、`last_collector_proxy_id` 和 `collector_extended_count`；私有尝试标识不返回。页面读取不会触发采集。

观测诊断字段均为兼容性可选字段：`request_sent_at`、`outbound_action`、`outbound_source`、`maintenance_reason`、`business_delivered`、`observation_id`、`snapshot_version`、`snapshot_expires_at`。交付标记只用于已完成的业务请求；采集不伪造业务交付，快照字段只描述实际注入的冻结快照。本次诊断修复不新增数据库迁移。

长度和块数是加密封装的可观察形态，不是 HTTP 状态码，也不证明模型质量。系统检查 Base64url、Fernet 封装及签发时间，不解密或验证未知密钥的签名；240 秒是本地维护策略。提供的 HAR 中五次 Responses 均请求 Astra、声明 Luna、返回 312 且携带 Cookie，没有 292 成功样本，不能据此证明 Cookie 或固定寿命对模型路由的因果关系。

## HTTP Cookie 兼容

只有凭据母账号启用 turn-state 缓存且请求参与缓存维护时，普通 HTTP、Responses 透传、native transport、插件业务转发和 WS→HTTP 桥接才池化替换 Cookie。关闭时完全旁路本功能，保留各路径原有头部规则，不额外放行客户端 Cookie。插件接管前同样校验冻结票据包；插件未接管时由内置发送链重新校验，只捕获实际发送的响应。无模型的用量、模型目录、刷新等辅助请求不读取票据包；未绑定账号的 OAuth 流程继续使用独立临时内存池。

遵循 Codex HTTPS 主机规则和名称白名单（包含 `__oailb`、`__cflb` 等），以及 Domain、host-only、Path、Secure、Max-Age / Expires 和删除语义。每次物理请求暂存自己的 Set-Cookie，成功结束并接纳目标票据后，与票据在同一数据库事务中 CAS 发布。独立采集还需通过响应模型校验。异常、无票、失败、超时及迟到结果不改已有包。独立采集从空 Cookie 集合开始；业务响应仅更新本次实际发送的快照，不混入其他模型或尝试的数据。

票据包按母账号、最终模型及授权代次隔离，同模型跨系统共享，保存包的实际协议及来源出口。“使用出票代理”只控制复用时的业务出口，不放宽协议、来源代理、授权及期限校验。HTTP 发送冻结完整包；发送前和提交时检查缓存总开关、授权、缓存和代理连接代次，缓存总开关关闭后重新开启也不会复活旧尝试。自然学习的新票绑定该次真实发送的协议及出口，同票跨出口响应不重标旧包的来源；协议不匹配只旁路、不删除其他协议的包。不采用客户端 Cookie、不导入 HAR 值，不额外请求 Cookie。原生 WebSocket 完全旁路票据功能：不注入缓存、不学习票据、不延长采集活跃期或建立采集需求，也不自动收发 Cookie；客户端原有字段按既有规则转发。WS→HTTP 桥接按实际 HTTP 出站处理。既有下游 Set-Cookie 放行规则不变。

Cookie 快照加密保存至 PostgreSQL，包含目标包的会话 Cookie，以支持跨实例及重启。包不超出票据的 240 秒本地寿命，显式 Cookie 到期时间不能延长；HTTP 包可复用期限取票据与所含 Cookie 的最早到期时间。成功目标没有 Cookie 时允许空包。包过期、损坏或存储不可用时，业务按原请求继续，不发送残缺包，不重放业务；包不可用不证明上游票据失效。Cookie 不参与导入导出、日志、遥测或管理接口，诊断只含名称、来源和到期时间。

最近票据观测分别显示 JSON 上游模型、关系、冲突、证据来源，以及 `safety-buffering-enabled` 和 `safety-buffering-faster-model`；后者不替代 JSON 声明。所有这些信息均属于同次 HTTP 响应和同次票据，没有新票据时不拼接到旧观测。缓存卡片中的最近响应证据同样不表示缓存自身的模型绑定。

本次整合参考版本的 Lite 采集模板与 HTTP 出票代理绑定，保留本项目严格验收及三次异常轮换，不引入 Mihomo、订阅管理、并行采集控制台或业务身份清理，不仅凭票据长度收票。

## 共享授权恢复与升级

`accounts.credentials` 是唯一 OAuth 凭据源；私有元数据只保留授权代次、CAS 和暂停来源，不保存第二份 token。常规刷新不换授权代次，显式重新授权或撤销才换代。永久授权失败会原子更新账号错误并停止调度；迟到失败不能暂停新授权。重新授权仅恢复仍由该授权错误持有的暂停，不清除人工禁用、真实限流或其他错误。编辑页保留三系统身份管理，授权沿用账号原入口。

账号调度恢复到引入多系统授权前的规则（`41501a3de`）：按原账号状态、分组、模型、配额、并发及冷却条件选择账号，系统信息不参与账号准入。调度摘要不包含 token，也不包含额外的 OAuth 可用性判定；旧摘要中的授权标记被忽略。选中账号后才分配对应系统的 UA、installation ID 和会话根，未知系统使用该账号默认系统。Spark 的账号调度规则不变，身份与凭据继承母账号。

token 获取恢复原缓存优先、刷新时机及失败处理策略，后台刷新候选按账号凭据和账号冷却筛选。401／403、测试成功恢复及重试耗尽继续修改原账号状态；私有授权状态不构成第二道门槛。保留授权代次与版本，仅用于防止旧刷新、旧失败或旧测试结果覆盖并发更新的凭据和账号状态。同一请求或 WebSocket 连接保持首次选定的系统身份，重试期间更改默认系统或安装 ID 不改变已冻结的身份。

升级必须先排空并停止旧进程，备份数据库后统一应用迁移 256、257，再启动新版本，禁止新旧写入逻辑混跑。256 将现有共享授权完整迁回账号，已撤销授权清除且不得从旧镜像复活，需重新授权的账号同步停止调度。257 清空旧票据、旧 Cookie 与旧尝试，按母账号／模型归并业务活跃时间、历史消费水位及最近完整代理状态，保留真实冷却；活跃模型重新采集，空闲模型等下一次业务。迁移不请求上游、不自动刷新授权；当前合法授权无需重做。回退旧程序前必须恢复对应数据库备份，不能让旧代码写入新结构。
