# OpenAI OAuth 三系统独立授权

> 历史实现文档：迁移 255 起已改为账号共享一份授权。当前行为与升级要求见
> [共享授权与三系统身份](OPENAI_SHARED_OAUTH_AUTHORIZATION.md)。以下仅保留旧版本设计记录。

常规 OpenAI OAuth 账号分别保存 Windows、macOS、Linux 授权。三套 UA、安装 ID 和
会话根仍是安装身份配置；生成了安装身份不代表已经授权。三个授权槽必须属于同一个
ChatGPT 用户及工作区，不能把同一 refresh token 复制到另一系统槽。

## 升级

升级前排空并停止所有旧版本进程，再执行数据库迁移和启动新版本。不要混跑仍按单份
凭据写入的旧进程。迁移 251 增加私有授权存储，并将已有凭据仅绑定到账号当前默认
系统；另外两系统保持未授权。迁移 252 将 turn-state 的缓存及采集运行态按系统隔离。
已有 installation ID、UA、根与账号总并发、计费、配额保持原有归属。

迁移与请求补全均幂等。撤销默认系统的授权后，该系统仍是默认，缺少系统信息的请求
会停止使用该账号；需要管理员明确选择另一个已经授权的默认系统。

## 管理操作

- 创建账号时选择首个授权系统，该系统成为默认系统。其他系统需要分别完成授权。
- 编辑账号时，三系统卡片显示各自授权状态、过期时间及脱敏错误，可单独授权、重新
  授权、撤销授权或选择默认系统。Spark 使用母账号的对应系统授权。
- 账号测试、导出 `auth.json` 和 turn-state 详情都可选择系统。省略系统参数的旧接口
  使用账号默认系统；不会自动借用其他槽。
- 每份 `auth.json` 只包含所选系统的标准 Codex 凭据。导出不刷新授权、不调用上游。
- 多系统备份使用明确的系统授权映射；导入凭据不复制安装身份、会话根、缓存、计数
  或私有版本。新增授权槽需要服务端验证，普通账号编辑不能修改受管 OAuth 凭据。

带系统授权的账号备份使用 `version: 2`，记录 `openai_oauth_default_os` 和按系统命名的
`openai_oauth_authorizations`，每项包含该槽的 `credentials`。没有系统授权扩展的其他
平台备份仍使用原格式；旧版 0/1 备份可导入，但不能把多系统字段塞入旧版本。已撤销的
默认系统可以与其他已授权槽一起恢复，也可以恢复全部已撤销的状态；恢复不会自动选用
另一个默认系统。备份包含真实凭据，应按敏感文件保管。

如需通过管理 API 明确切换 OAuth、PAT 或 Agent Identity 模式，更新请求必须同时提供
`openai_auth_mode_change: true` 和合法的 `credentials.auth_mode`。普通表单或后台旧快照
没有这个动作标记时，不能更换当前受管授权模式。该标记不代替目标模式的凭据校验。

授权 state 在服务端绑定账号、系统、用途及授权代次，只能消费一次。回调不能更换
目标系统或账号；不同用户或工作区的授权被拒绝。

## 请求及后台任务

系统识别沿用原始 UA 和可信本轮环境上下文规则，结果在选号前冻结。明确识别到的
系统只使用对应槽已授权的账号；没有可靠系统信息时，分别检查每个候选账号的默认
系统。普通调度、粘性会话、`previous_response_id`、重试换号和指定账号入口执行同一
授权检查。WebSocket 物理连接冻结系统及授权代次，撤销或重新授权后旧连接不得继续
借用新凭据发送。

OAuth 刷新锁按凭据账号和系统隔离；缓存与写回还校验授权代次及版本。正常刷新保持
安装身份和根；重新授权或撤销使该槽旧结果失效。认证失败只影响对应槽，账号级配额、
429 冷却与总并发继续共享。

turn-state 的票据、历史、需求和代理轮换按系统隔离，后台采集仍按凭据账号单飞并遵守
共享冷却。遥测池仍按系统和安装身份保留，批次额外冻结授权代次，发送时读取该槽最新
凭据；旧授权批次跳过，不借用默认槽或把旧统计合并到新授权。

API Key、PAT、Agent Identity、setup-token 和其他平台不进入三系统 OAuth 授权规则。
私有凭据和授权代次不进入普通账号摘要或公开观测。数据库凭据沿用本项目现有存储设施，
本次变更不增加或宣称额外的全库静态加密。

验证范围及既有失败见 [验证记录](OPENAI_OS_OAUTH_AUTHORIZATION_VERIFICATION.md)。
