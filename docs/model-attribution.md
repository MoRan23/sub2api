# 降智检测

管理员在侧边栏「降智检测」配置 LM Fingerpoint Detector 内网服务地址、探针模型、期望模型列表及高低级白名单。
迁移 `263_model_attribution.sql` 初始关闭自动检测，默认探针模型为 `gpt-6-astra`。
服务地址及两份非空白名单配置完成后才能开启。模型选择器支持手动输入具体模型 ID。
「测试连接并获取候选模型」只查询服务身份、版本和指纹库；实际归因探针会消耗上游账户额度。保存配置时后端再次核实版本；检测期间服务换版会记为异常，需管理员重新检查并保存。

## 内网服务与升级

配套服务直接复用 [Ikaleio/lm-detector](https://github.com/Ikaleio/lm-detector) 的官方模块。首版固定提交 `d53d3f5b158249a87a895e4fc7aaa8a940dfd6d6`，算法和参考库一起发布，运行时不下载更新。服务不接收账号密钥、不请求模型、不持久化探针回答。

使用标准或 local Compose 配置时，在 `deploy` 目录执行：

```sh
docker compose -f docker-compose.yml -f docker-compose.lm-detector.yml up -d --build lm-detector
# 使用 local 配置时，将上面的 docker-compose.yml 替换为 docker-compose.local.yml。
```

容器加入现有 `sub2api-network`，不发布宿主机端口。降智检测页面填写 `http://lm-detector:8080`，检查连接和版本，保存后开启自动检测。使用其他 Docker 网络的安装需将分析容器接入 Sub2API 所在网络；不要对公网发布分析端口。完整内网协议和离线测试见 `services/lm-detector/README.md`。

迁移 `267_lm_fingerprint_detector.sql` 会关闭自动归因、清空旧服务地址、递增配置版本并清零连续次数，保留分组、模型、名单、首测偏好及历史。旧活动归因任务终止为「检测器已切换」，不重放、不再应用结果。迁移不改变账户当前白名单，也不停止或删除旧 ModelTrace 容器。部署更新后由管理员完成连接检查再启用；鹈鹕首测配置保持不变。

## 检测和分组

- 每个符合条件的 OpenAI OAuth 实体账户及 Codex-Engine 模式的 OpenAI API Key 账户每 10 分钟开始一轮检测；扫描间隔 30 秒，不同账户同时执行。需配置并启用自动检测，Engine 账户沿用全局及分组检测策略、期望模型和白名单规则。
- OpenAI API Key 账户均支持单账户及批量手动归因检测；其中普通通用或透传账户仍仅手动，账户列标注「仅手动」，Codex-Engine 账户不显示该标注。API Key 账户均不参与新账号自动首测，鹈鹕测试范围保持不变。手动检测需要配置 LM Fingerpoint Detector 地址并完成版本检查，不要求开启自动检测；不受停用、关闭调度、过期、透传、影子账号或本地限流标记限制。仍需账户存在、授权有效，且仅支持 OpenAI OAuth / API Key 账户。
- 手动弹窗支持从检测器候选列表选择探针模型，也可输入具体模型 ID；默认跟随各账号的分组 / 全局模型。期望列表默认继承各账号生效配置，也可「单独设置」统一用于本次所选账号；单独设置为空时跟随各自本轮探针模型。所选探针、生效期望列表及原始覆盖选择保存到任务快照，不修改自动检测配置。同账号的启动中、检测中或等待重试任务均视为活动任务；再次点击返回已有任务，不覆盖它的模型或期望列表。
- 全局配置提供「分组优先级」排序列表（`group_priority`），越靠前越优先。多个分组的账户先选定优先级最高的所属分组，再取配置：启用独立配置时采用其高级、低级白名单及探针模型；继承全局或未设置独立配置时采用全局配置，不再跳到后面的分组。未列出的分组按 `account_groups.priority` 升序、分组 ID 排在后面，也参与选择。记录中保留选中的分组 ID；无所属分组时使用全局默认，分组 ID 为零。
- 探针模型决定实际请求；期望模型列表决定哪些归因结果可以通过。全局和分组均可设置，列表为空时要求最高候选等于本轮探针模型。三条独立探针依次使用所选账户的 OAuth 或 API Key 授权及账户代理执行；OAuth 使用默认授权环境。绕过业务白名单与模型映射，不提供工具、不修改健康状态、不产生下游用户扣费。
- 归因检测遇到明确的 HTTP 503 或 SSE 错误状态 503 时，持续重试失败的当前探针，保留已成功回答；不受两次重试或十分钟总墙钟时间限制。状态码优先于限流错误代码，503 不会因 `rate_limit_exceeded` 被误判为 429；没有明确状态码时沿用原有限流判断，不猜测错误文案。503 从 2 秒指数退避，最高 60 秒并带抖动；合法 `Retry-After` 可延长等待，最多采用 300 秒。
- 其他临时连接失败、响应超时、流中断、HTTP 408/500/502/504 等仍最多额外重试 2 次，普通重试次数不会因经过 503 等待而清零。非 503 探针执行及普通重试等待共用十分钟预算；明确 503 的请求耗时与等待不扣此预算，每次实际请求仍有独立超时。授权变化、取消、参数错误或输出超限不重试。鹈鹕测试和普通网关请求保持既有重试及超时规则。详情记录累计重试次数和全部已报告用量，重试会消耗上游额度。
- 当前账号或直接请求的探针模型被本地标记限流时，自动归因及鹈鹕测试跳过；手动归因忽略本地标记。实际 HTTP 429 或流内明确的限流错误仍立即停止，不重试、不继续后续探针，也不修改模型名单。过期限流标记不阻止检测；周期检测在限流解除后恢复，新账号首测跳过后不补发。诊断请求仍不改写账号健康状态。
- 停用、关闭调度、过期、删除或共享凭据的影子账户仍跳过自动检测；自动透传的 OAuth 账户也跳过。Codex-Engine 模式不受普通透传配置影响，仍遵守上述状态及本地限流跳过规则。
- 上述自动资格在入队时检查。任务启动后，启停、调度开关、过期时间、换组、分组优先级、名称和模型映射变化均不中断当前检测；探针固定使用冻结模型且绕过映射。代理变更从下一次尝试生效。账号删除、凭据所有者或授权代际改变、API Key／地址更换、认证类型或 Engine 接入模式变化仍终止测试；同一授权代际的正常 token 刷新允许继续。
- 内网分析服务通过 `GET /api/info`、`GET /api/banks`、`GET /api/challenges`、`POST /api/analyze` 提供固定版本身份、模型库、题目和分析。仅发送模型原始完整回答和期望数量，不自行提取、截断或补齐数字，绝不发送账户令牌。
- 每轮开始前必须确认全部生效期望模型均在参考库中；缺少任一个即异常，不发送模型探针。探针 ID 本身无需在库中，因此可用业务别名探测并接受明确的真实模型。服务不可用、版本改变、回答未全部有效、校准不可用、置信度无效或最高置信度并列都记为异常。
- 官方完整三样本模式生成参考库内的闭集置信度；`decision: not_confirmed` 不表示执行失败。置信度不是模型身份证明，界面保留此说明；未校准值显示「不可用」而不是 0%。不启用分词器探测、额外采样或重训。

账户列表「归因测试」列分别显示活动任务与最近结束的结果，支持单账户和批量立即测试。手动测试与自动测试共用去重与名单切换规则。关闭归因弹窗不触发账户列表刷新。

## 新 OAuth 账号首测

「降智检测 → 新 OAuth 账号首测」提供归因、鹈鹕两个独立开关（默认开启）及独立模型：`attribution_model` 默认 `gpt-6-astra`，`pelican_model` 默认 `gpt-6.1-sol`。归因首测还要求全局检测已经配置并启用；鹈鹕首测独立于全局检测开关。模型级限流分别检查各自模型，不阻止另一种未限流的首测；账号整体限流仍跳过两种测试。

设置仅影响保存后新建或导入的 OpenAI OAuth 实体账号，不补测旧账号。创建时保存首测选择，每 3 秒检查并启动；停用、关闭调度、过期、删除、自动透传及影子账号跳过。启动前再次检查当前开关，已手动测试的账号不额外重复首测。两种测试消耗上游额度，采用上述临时错误重试规则。

归因首测的期望列表默认继承账号生效配置，也可单独设置，空列表跟随归因首测模型。独立首测选择与账号创建事件一同保存，后续修改首测设置不覆盖已经创建的事件；高级、低级名单仍按分组规则选择。后续十分钟周期使用原全局 / 分组探针和期望配置。关闭归因首测只取消这一次即时测试，不关闭周期检测。探针或生效期望列表不同会分别建立有效判定基线。

迁移 `264_new_account_tests.sql` 新建创建事件表。账号、首测事件同事务保存；两种测试的入队与事件消费也同事务提交，多实例、重启及历史清理都不重复触发。每个账号仅一条事件，不保存令牌或回复，物理删除账号后级联清理。

迁移 `265_split_initial_test_models.sql` 拆分模型配置并递增配置版本。旧共用模型保留为归因首测模型；鹈鹕的旧默认 `gpt-6-astra` 更新为 `gpt-6.1-sol`，其他自定义共用模型保留。已创建事件保留原有模型，保存新配置不会改写待启动任务的模型，也不重放已完成任务。

## 白名单规则

最高置信度模型 ID 属于本轮生效期望列表即通过，使用精确匹配，不累加多个模型概率、不另加置信度阈值。只有唯一最高候选才能判定；即使并列者都在列表中也记为异常。例如探针使用别名、期望列表为 `[gpt-6-astra, gpt-6.1-sol]` 时，最高候选为其中任意一个都通过。

| 当前结果 | 连续通过次数 | 行为 |
| --- | --- | --- |
| 通过 | 第一次 | 保持当前白名单，等待再次通过 |
| 通过 | 连续第二次 | 应用高级白名单，内容相同不重复写入 |
| 通过 | 已确认连续两次 | 不修改 |
| 不通过 | 任意 | 应用低级白名单，内容相同不重复写入 |
| 失败 / 异常 / 跳过 / 取消 | 任意 | 不修改，不覆盖有效判定，打断连续通过 |
| 完成但策略不兼容 | 任意 | 保存真实判定，不更新白名单，不累计升级 |

每轮包含三条探针，连续两次指两轮完整检测均通过。两轮的最高候选可以不同，但必须满足同一份生效期望列表。首次检测及降级后恢复均需连续通过两次；不通过、执行失败、异常、已跳过、超时、中断或过期结果会将连续次数清零，未启动的周期扫描不计作一轮。详情显示「已通过 1 次，等待再次通过」及连续次数（最多显示 2）。
配置版本或有效策略变化后重新累计：不通过立即同步低级名单，通过需连续两次才同步高级名单。连续判定基线不包含分组 ID 或更新时间，换组但有效探针、期望模型、高低白名单、配置版本、检测器和授权均相同时仍可累计。OAuth 普通刷新保留基线，重新授权、更换探针模型或生效期望集合后重新建立基线。未配置列表的旧配置继续跟随本轮探针；旧历史按自己的快照解释，不套用当前期望列表。
手动测试也使用已配置的高低级名单；未配置完整两份名单时只保存结果，不清空模型映射、不标记名单已同步。手动选择不同模型的判定不会被当成自动模型的已同步基线。
API Key、上游地址或 Codex-Engine 接入模式变化同样重建基线，并阻止旧任务回写名单；仅保存授权摘要，不持久化密钥到检测记录。

更新只替换 `credentials.model_mapping` 中 `key == value` 的白名单条目；别名、通配符及冲突键的原映射保留。这些映射继续按现有业务路由规则提供访问。

结果应用、JSONB 字段更新、有效判定、连续次数和调度缓存 outbox 事件处于同一事务，不覆盖其他凭据字段。执行有效性与白名单回写资格独立校验：完成时按当前策略重新应用本轮原始覆盖选择，核对有效探针、期望列表、高低白名单、配置版本、检测器、授权及管理员映射修改。新组策略不兼容或管理员已改映射时仍保存真实的通过／不通过判定，并标注「策略已变，未更新白名单」，不覆盖新名单、不累计升级。未提交的名单变更不记为同步成功。

迁移 `266_attribution_consecutive_passes.sql` 为有效判定表增加连续次数。升级时从零开始累计，不推算历史记录、不立即修改已有白名单。

迁移 `268_attribution_expected_models.sql` 只为首测事件新增可空 JSONB 列，保存独立期望列表。原有配置、任务、历史、连续次数及自动检测开关均保留；旧事件默认继承。设置期望列表不会立即改账号名单，待有效检测按上述规则处理。

## 执行和存储

- PostgreSQL 唯一活动任务索引与事务锁保证同一账户的同类测试不重叠，支持多实例。取消全局三账户容量限制，领取后立即并行执行，不等待其他账户结束。保留数据库 `queued` 状态作为创建到领取的短暂启动阶段，界面显示「启动中」；不用于限流排队。鹈鹕重复触发标为已跳过，旧版尚未开始的重复任务也会跳过，不追加到后续执行。
- 运行租约 45 秒，每 10 秒续期；续期/校验有 5 秒上限。成功探针和明确 503 的进度通过带 claim 校验的事务保存。进入 `retry_wait` 后释放执行协程、连接及并发资源，记录下次尝试时间，到期重新领取。
- 503 等待任务在重启后恢复同一轮，只执行失败的当前探针，不重复已成功探针；重启时仍在执行且结果不明的任务记录中断，不盲目重放。普通重试次数、非 503 剩余预算和已报告用量随检查点恢复；停机期间的周期不补发。
- 管理员可取消启动中、检测中或等待重试的任务。取消幂等，不修改白名单且打断连续通过；任务租约和 claim 校验防止取消后或过期执行器继续写回结果。
- 每账户只保留最近 100 条已结束任务。有效判定和连续次数独立存储，重启与历史清理不影响恢复。
- 活动任务的内部检查点保存冻结挑战、成功的完整回答、探针位置、重试次数和剩余预算，仅供恢复使用；完整回答不返回管理页面、不写日志，任务结束或取消时清除，不保存 OAuth 令牌。详情只展示完成探针数、累计重试、下次尝试时间、配置快照、检测器版本、置信度、排名分数、校准状态、有效性诊断、用量和名单变更。检测器版本参与判定基线，新旧检测器不能共同累计两次通过；旧历史标注 ModelTrace 且不会重新执行。
- 配置保存使用版本校验，冲突返回 HTTP 409。

迁移 `270_attribution_retry_checkpoints.sql` 增加等待状态和内部检查点，不改账号名单或自动检测开关。旧版尚未结束且没有可恢复检查点的任务会标记为中断，并打断连续通过；已有结束历史保留。升级后的 503 等待任务可在重启后继续。恢复时同时核对实际凭据所有者、OAuth 授权槽位及代际，避免把不同授权下的回答拼成一轮。

管理员 API 前缀为 `/api/v1/admin/model-attribution`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / PUT | `/config` | 读取 / 按版本保存配置 |
| POST | `/models` | 检查连接，返回 `models` 及 `detector` 版本信息；保存配置时带回所确认的 `detector` |
| POST | `/jobs` | 为 `account_ids` 创建手动去重任务；可选 `model` 覆盖本轮探针，`expected_models` 覆盖本轮期望列表 |
| GET | `/jobs` | 分页查询，可传 `account_id` |
| GET | `/jobs/:id` | 结果详情 |
| POST | `/jobs/:id/cancel` | 幂等取消活动任务，返回任务状态；不修改白名单 |

全局与分组策略的 `expected_models` 缺失或为空数组表示跟随本轮探针。手动请求的 `expected_models` 与首测配置 `new_account_tests.attribution_expected_models` 省略或为 `null` 表示继承账号配置，显式 `[]` 表示单独跟随本轮探针，非空数组表示独立期望集合。最多 500 个具体 ID，每个不超过 200 字符，去首尾空白并去重，不支持空 ID、空白字符或通配符。任务快照保存解析后的非空列表。

## 本地验证

使用固定参考样本、官方函数对比、模拟分析服务与上游，以及独立 PostgreSQL/Redis 容器，不发送真实模型或支付请求。

- Go：配置选择、跳过条件、三探针链路、数值验证、上游失败、取消/超时、绕过名单、既有鹈鹕传输/OAuth 刷新回归。
