## Three-round performance / 三轮性能

See [final three-round ranges](v0.2.23/performance-final.md), [initial raw logs](v0.2.23/raw/performance), [final parser raw logs](v0.2.23/raw/performance-final), and [runner](v0.2.23/run-comparison.py). CPU affinity is fixed at `0x55`; baseline/merged run serially, with the second round's order reversed. All measurements use the same fixtures. After removing two temporary allocations, only the affected usage parsers were compared for another three rounds. The initial [comparison](v0.2.23/performance.md) is retained. Values below are medians.

| Scenario | Baseline → merged | Observation |
|---|---|---|
| DeepSeek, about 1 MiB / 300 turns | 172.6 ms → 1.254 ms; 515.3 MB → 2.36 MB allocated | Time −99.3%, allocation bytes −99.5% |
| Ollama, about 1 MiB / 300 turns | 184.6 ms → 2.461 ms; 520.1 MB → 3.70 MB | Time −98.7%, allocation bytes −99.3% |
| 128 raw SSE frames in one read | 339.8 µs → 314.9 µs; 258 → 1 flush | Flushes −99.6%; time −7.3% |
| 8 MiB, 15 retry transforms | 261.5 ms → 258.9 ms; allocation bytes unchanged | Existing retry preparation preserved |
| Large catalog capability cache | 539.6 ns → 523.7 ns; 424 B / 6 allocations unchanged | No full catalog copy on a capability hit |
| Authenticated queued usage lifecycle, 1 MiB | 601.0 µs → 575.1 µs | Similar total allocation; small fixed snapshot overhead |
| 128 blocked billing tasks, each sourced from distinct 1 MiB bodies | About 3.5–3.8 KB retained per task before and after | No reintroduced whole-body retention |

Final usage parser medians range from −1.0% to +2.9% time. Passthrough usage events remain 0 B / 0 allocations; map-based and full response parsing keep the original allocation count, adding only 16 bytes of necessary presence/state storage. The initial temporary DTO and absent-field pointer allocations were removed. Raw-stream timer state adds about 143 bytes / 3 allocations per request. These are bounded event/request metadata, not copies of request bodies or catalogs. Per-round ranges are retained, including noisy baseline samples. The GC-controlled retention benchmark's ns/op includes GC and is not used as throughput evidence.

New canonical GPT-6.2 template lookup is 0 B/op / 0 allocs/op ([allocation observation](v0.2.23/raw/catalog-template-allocations.log)). Local benchmark results describe the measured paths; production CPU, RSS, network throughput and p95 latency were not sampled during this merge.

## Limits and delivery / 未执行与交付

- Targeted affected suites were run, including race; the unrelated whole-service suite and live upstream smoke tests were not run. The known live-calling `TestUsageProbeSkipsUnavailableSharedGrant` is excluded explicitly.
- A broader parser selector also picked up three unchanged `ForwardAsAnthropic` identity fixtures: `InjectsPromptCacheKeyForAPIKeyMessagesDispatch`, `AutoDerivesPromptCacheKeyWhenMessagesDispatchHasNoSessionID`, and `APIKeyMetadataSessionSurvivesChangingCacheControlAnchorAfterContinuationDisabled`. They expect the legacy cache-key value/prefix while the local identity policy produces isolated fallback UUIDs without an HMAC secret. All three fail identically on the compiled `e47c186b6` baseline ([baseline record](v0.2.23/raw/identity-baseline-failures.log)); identity isolation was preserved. The directly affected usage/TTL selector is tested separately after the allocation fix.
- Existing frontend build warnings remain: old Browserslist data, mixed static/dynamic imports, large chunks, and DEP0190. They did not fail typecheck, lint or build.
- No deployment or production configuration change. Existing detector modifications and six investigation files remain in the primary checkout.
- Remote CI is recorded separately from local validation. GitHub's public workflow listing still contains active workflow definitions; repository-wide Actions permissions were not changed or queried with administrator credentials. No workflow was enabled or manually dispatched. The final pushed revision's run listing is checked separately.
- Source merge commit: `24923e658`, parents `e47c186b6` and `2af3f1e15`. Normal merge and separate validation documentation are delivered through `origin/dev`; no force push.
