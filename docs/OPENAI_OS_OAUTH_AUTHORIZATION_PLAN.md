# OpenAI OAuth 按系统独立授权

基线：`dev@41501a3de`。用户已确认：既有单份 OAuth 授权保留在账号当前默认
系统，另外两个系统等待重新授权。

## 行为

- 常规 OpenAI OAuth 账号有 Windows、macOS、Linux 三个授权槽，各自保存独立
  OAuth 授权、刷新状态和安装身份；三槽必须属于同一个上游账号与工作区。
- 明确识别到某系统时，只调度该系统已授权且可用的账号。不借用其他系统的
  凭据，不把缺授权当作可以通过刷新补齐的情况。
- 入站系统未知或缺失时，在每个候选账号上使用其默认系统。默认系统必须有
  可用授权；不能在请求入口提前把未知系统统一改成 Windows。
- Spark 继承母账号对应系统授权，保留业务账号归属。API Key、PAT、Agent
  Identity、setup-token 和其他平台不进入本规则。
- 账号总并发、配额、分组、计费和账号级限流维持共享；授权失效、刷新错误
  和需要重新登录的状态按系统隔离。

## 存储及迁移

- 在现有三系统身份存储旁增加私有授权记录，键为凭据账号 ID 与系统，保存
  授权数据、授权代次、刷新 CAS 版本、授权来源、时间及脱敏状态。
- installation ID、UA 和根仍是安装配置；有配置不代表已授权。
- 在账号行锁内一次性将旧授权绑定到当前默认系统，另外两槽保持空。迁移
  标记防止请求补全、重启或旧编辑快照把同一授权再次复制到其他槽。
- 保留旧 `accounts.credentials` 的默认系统兼容镜像。普通编辑、批量更新、
  用量更新、后台旧快照不能覆盖私有授权；授权与刷新通过专用事务接口写入。
- 私有凭据不放进公开 OS profile JSON。管理接口只提供授权状态、有效期、
  脱敏错误等摘要；调度缓存只保存授权资格与版本摘要。
- 默认系统变更与兼容镜像同步提交。旧授权保留期间不会因默认系统切换复制
  token；选用的是目标系统已经建立的授权。

## 授权入口

- OAuth 授权开始时将账号、系统和用途固定进服务端 PKCE/state 会话。完成
  授权时从该会话恢复目标，不允许客户端在最后一步换系统或换账号。
- 现有账号授权完成后，服务端验证账号主体并原子更新指定槽。拒绝把不同
  ChatGPT 用户或工作区的凭据装入同一账号的其他系统槽。
- 新建账号明确首个授权系统，该系统成为默认系统。其他槽只生成安装配置，
  不复制首槽授权。
- 首次授权、重新授权和解除授权均明确目标系统。重新授权只失效本槽的旧
  凭据关联数据；正常 token 刷新不重建 installation ID 或会话根。
- 现有手动 token、refresh token、Codex 导入等入口要携带明确系统；导入
  已有凭据不能被描述成完成了另一系统的新 OAuth 登录。禁止简单复制已有
  槽的 refresh token 作为另一个系统的独立授权。
- 令牌交换与刷新也使用所选系统身份，不能仍固定使用 canonical 系统 UA。

## 调度及请求冻结

- 在账号选择前从原始 UA、可信本轮环境上下文识别系统，保存不可变的请求
  系统快照，包括“已解析但未知”。不从归一后的正文或 UA 重新推断。
- 普通选号、advanced/TopK、sticky、`previous_response_id`、重试换号、
  指定账号路径统一检查授权资格。选中后读取最新指定系统凭据并二次校验。
- Redis 调度 metadata 增加无密钥资格摘要，明确哪些账号需要 OS 授权，
  避免将 PAT/Agent Identity 或 Spark 误判为常规未授权账号。
- Responses、透传、Chat、Messages、HTTP/WS bridge、原生 WS，以及已有
  Images、count/input tokens、Live、模型目录等相关 OAuth 入口一起覆盖。
- 同请求重试保持识别系统；换账号后使用新账号的对应授权。WS 物理连接
  冻结授权槽和身份；撤销或更换授权后，旧连接不能切用另一系统继续发送。
- 若目标系统没有合格账号，返回明确的无可用授权账号结果，不静默跨系统。

## 刷新与后台状态

- OAuth token 缓存和刷新锁按账号、系统及授权代次隔离。获取锁后重新读取
  同一系统授权，用版本 CAS 写回，不能因 GetByID 得到默认镜像而写错槽。
- 后台刷新遍历已授权槽；未授权槽保持静默。授权失效只暂停对应系统。
- turn-state 的缓存、需求、历史、凭据代次与代理轮换状态隔离到授权槽，
  不让一个系统使用另一个系统采集到的票据。保留账号级采集单飞和共享限流。
- 遥测沿用现有系统/installation 池，批次额外冻结授权槽及授权代次；发送
  前读取该槽最新凭据，不能使用账号默认系统的 token。未授权系统不驱动池。
- 独立维护任务使用默认系统或任务已绑定的系统；缺授权时跳过并记录原因。

## 管理页面和导入导出

- 三系统卡片分别显示未授权、可用、刷新中、需要重新授权等状态；可对指定
  系统授权或重新授权。默认系统从已授权系统中选择。
- 账号测试明确所测系统，使用同一槽的凭据与安装身份；缺授权时在发送前
  返回错误。测试成功不能顺便清除其他系统的授权错误。
- `auth.json` 导出增加系统选择，只导出该系统的一份官方格式凭据；不把
  多个系统塞进同一个 auth.json。省略系统的旧调用兼容默认系统。
- 旧账号导入仅作用于默认系统；新格式可携带显式系统授权映射，逐槽核对
  主体和写入意图，不导入安装 ID、根、运行态及私有版本。
- turn-state 详情增加系统选择，沿用当前紧凑模型列表和颜色规则。
